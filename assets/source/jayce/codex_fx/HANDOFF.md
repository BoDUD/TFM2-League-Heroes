# 杰斯第3步：31张特效交接

31张均已用内置 image_gen 单独生成：21张动画特效条、10张动作帧透明特效。没有用代码绘制闪电、火花、圆环或门柱。原稿原样保存在raw/；派生图做读格、颜色/透明校准、位置校准和镜像校准。未导入游戏或修改其他动作。

## 文件

- 根目录31张PNG，每张独立交付；pixel_1x/中有31张对应逻辑格PNG。普通特效统一交付8倍；生图提示中的普通图16px/格、大图8px/格与交付倍率分开记录。
- raw/：31张选用的模型原稿，若有补画，旧稿在raw/attempts/，均未重采样、未清理。metadata/有原始来源、原稿SHA-256和读回参数。
- manifest.json：尺寸、逻辑格、逐帧切片矩形、帧数、调色板、对称方式、绑定、bake青色起点和原动作帧范围。
- generation-prompts.txt：各张提示词及参考图顺序；generation-plan.json为逐张计划。
- previews/：21组动画GIF、3张独立特效联系表，以及10张叠在淡灰定位图上的检查图与总览。预览的定位角色、网格和文字只用于检查，根目录bake PNG不含角色。
- references/保留用户的定位图与任务规格，未包含仅供本地参考的refs/lol_fx_ref.png。
- export_jayce_fx.py / qa_jayce_fx.py保留本轮读格与检查方法；脚本路径按本工作区编写，移动后需要调整。

## 原稿与派生图的差异

模型返回的长条常带上下留白，画布与像素密度也不一定等于提示中的16/8/6px。派生图从模型内容读回指定逻辑格：取alpha≥128且非黑的样本，至少20%有效覆盖才保留该格以免细电光消失；有效样本先贴近该图规定的调色板，再取多数颜色，不混合平均颜色。每格最终只有一个纯色，alpha0/255。这个过程没有补画新特效形状。

独立特效条先按模型画出的阶段分离内容，再整理为等宽帧；a_hit、e_blow、gq_hit、q_land、cq_boom、gq_boom使用逐阶段裁取框修正原稿不等距排布，其余按等宽阶段读回。垂直取样带按原稿内容高度与规格校准；动作特效把模型画出的孤立特效内容读入定位图上的目标区域，原始留白不作为绘图主体。具体裁取框、阶段边界及目标区域见manifest/metadata。这意味着bake的定位是派生图校准结果，不能声称原稿直接逐格命中所有坐标。

原稿没有全部逐格对称。派生图通常对每帧复制模型已有的左半或上半；w_zap从左右对应格选择有效且更亮的模型颜色，再同步两侧，以保留闪电连接。共校准3786个逻辑格；shred仅保留左右共有的形状，依规格保留左金右蓝，颜色不是左右相同。清除了206格模型产生的最深电蓝外边线；门柱的实体金色结构和削甲图标的紫色边保留。q_hit、tf_spark、hyper按规格额外清空身体避让区域，其矩形及清除格数已记录。原稿不受这些处理影响。

| buff中间、地面环内留空 | 见逐图目检说明；未把近黑半透明像素当作实体留底 |
| bake同定位图大小/格子，只画特效、不遮脸 | 10张尺寸、6px格、脸部排除区透明检查通过；根目录无定位人物/线框 |
| bake起点对准青色十字 | 用目标区域校准；下表列青色起点到最近特效格距离，只证明附近有特效，不是精确核心对准的证明 |
| bake线条至少3格粗 | 10张主光团均有3×3实心区域；这不是所有分支最小线宽证明，细枝、末端、小火星仍需逐格复核 |
| raw未改动 | SHA-256核对通过 |
| 最后写HANDOFF并打包 | 全部生成、读回、自查、manifest写完后，最后写本文件，再打包 |

逐帧亮芯检查未通过项：无（不等于每个孤立小火星都已认证有白芯）。
 
这是完整特效稿交付，尚未验证游戏内叠加、缩放、镜像、技能触发时机或循环接缝；细枝最小线宽、每个小光点的白芯及原稿定位密度不应标为严格验收通过。
