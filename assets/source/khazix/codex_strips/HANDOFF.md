# 卡兹克动作条带交接：第 2 步

## 文件和接入

交付 8 张 `khazix_<tag>.png`：保留提供的 idle，新增 run、attack、skill、skill2、ult、hit、dead 共 40 帧。连同 idle 共 46 帧。
正式条带透明背景、严格 8×8 块，单格 1024×768，对应 1x 的 128×96。
`khazix_cells.json` 是输入文件的原样副本；`manifest.json` 记录各帧矩形、pivot、bbox、时长、头部位置以及释放帧爪尖坐标。bbox 采用左上包含、右下不包含的坐标。
供导入的是根目录 8x PNG。`frames_1x/`、`*_1x.png` 和 `previews/` 用于检查；预览的背景和文字没有写进正式素材。
普攻第 4 帧 tick 11；Q 第 4 帧 tick 12；E→W 第 6 帧 tick 20；R 第 2 帧 tick 6。爪尖位置取释放帧中最右的可见骨白刃口像素，需在游戏内确认它是否适合作为特效发射点。
没有添加飞刺、虚空能量、隐身闪光或落地冲击，留给后续特效步骤。
本次没有写入项目或游戏目录，也没有执行 import_native.py、重新烘焙技能或游戏内模拟。

## 原稿与最终方法

七次生图的完整原稿保存在 `raw/<tag>_generated.png`，各次实际提示词见 `raw/generation_prompts.json`。每次使用同一动作的定稿造型、now 条带和 lol_pose 条带作为参照。
这些原稿的比例、头部和轮廓不能逐格符合定稿，因此没有作为最终条带直接缩放或删行使用。最终以已定稿的 1x 模型分离原像素部件，再按姿势重摆；原稿只作动作参考。源造型、头部和调色板也保存在 raw 中。
手臂连同镰爪整体按 45° 倍数旋转，肩部位置采用原造型关节点；远臂置于躯干后，露出的远侧刃口单独保留。站立动作的躯干和腿使用原像素。跑步用原腿像素行移位实现交叉步，远腿按原调色板降低一档；跃击和死亡可转动腿部。
头部按不透明掩码逐像素复制。除死亡第 5–8 帧随身体精确转 90°，其余帧头部只平移。跑步头部相对 pivot 的横坐标固定，纵向起伏 1 格。
抬臂时恢复与原远臂重叠的原髋部像素以维持连接。清除旋转或腿移位产生的孤立黑格，以及非头部、最多 3 像素的离散碎片。未通过缩小角色、删整行或重新画人体替换定稿模型。
`raw/build_khazix_strips.py` 为本次构建脚本，依赖原工作树 `tools/art/rigkit.py`；`raw/verify_khazix_strips.py` 为独立输出核验脚本。脚本保留本机相对路径，不是一个独立安装程序。

## 各动作使用的提示词与近似处

每项完整提示词均可按以下 tag 在 `generation_prompts.json` 找到。

| tag | 提示词动作主题 | 最终实现及仍需注意的地方 |
|---|---|---|
| run | 8 帧交叉步、头横向稳定、躯干起伏 1 格 | 原腿交叉、远腿暗一档，爪小幅摆动；用像素位移近似参考的连续关节运动。 |
| attack | 6 帧抬爪、下劈，第 4 帧命中 | 整块镰臂离散旋转和整人前移；没有生成新的曲面关节中间态。 |
| skill | 6 帧蓄力、前刺，第 4 帧命中 | 第 4–5 帧保持前刺姿势；采用原镰爪轮廓，没有重塑刀尖朝向。 |
| skill2 | 7 帧起跳、腾空、落地、甩刺，第 6 帧释放 | 腾空整人上移 5–6 格并收腿；第 1、4 帧的收腿姿势下移到脚底线；翼片整块展开。投掷爪保持原模型形状，没有另画张开的关节。 |
| ult | 3 帧展翅、交叉爪收翅、第 2 帧隐身时机 | 使用原站立躯干、交叉爪和翼片重摆；第 2 帧未另画更低的躯干，以保留站立身体像素。隐身特效尚未制作。 |
| hit | 2 帧后移受击、恢复 | 整人左移 2 格、镰臂旋转；没有另画压缩躯干。 |
| dead | 8 帧后倒，45°、60°、90°，最后保持 | 第 3–4 帧保持原面甲朝向，第 5–8 帧随整人转 90°并收腿；第 6–8 帧角色姿势一致，仅输入 pivot 不同。翼片沿用原图，没有另画压扁或皱折形态，因此落地轮廓仍是原部件的近似。 |

## 已核验与限制

- 所有正式图尺寸与对应 now 输入相同，帧数、顺序、pivot 和毫秒时长与输入 JSON 相同；skill2 的最后一格全透明。
- 正式图严格对应 1x 图的最近邻 8 倍放大；透明度只有 0 / 255，只有定稿的 23 色；每格第 82 行起全部透明。
- 独立核验确认 46 帧头部所有不透明像素都与头部模板一致，死亡旋转帧与精确 90° 模板一致。
- 新做的 40 帧均为一个 8 连通块，孤立黑格为 0；原始 idle 被逐字节保留，检测到它原有的 7 个孤立黑格也随之保留，没有修改输入待机。
- 死亡第 6–8 帧去除位置差异后逐像素一致。预览 GIF 的时间单位为 10ms，run 的 125ms 无法在 GIF 中逐帧精确表示；正式时长以 JSON 的 125ms 为准。
- 详细结果见 `verification.json` 与 `qa.json`。这些结果验证文件契约与像素一致性，不能代替手臂运动美感和游戏内效果的验收。
- 3D 参考中的自然关节曲线、翼片变形以及倒地压缩使用原像素部件近似，未完全重现。尚未验证卡片、HUD、英雄列表裁切及实际战斗中的动画过渡。

下一步可将根目录条带与 cells.json 接入原项目，再按 manifest 中的释放帧和爪尖坐标制作独立特效、核对技能时机并进行游戏内预览。
