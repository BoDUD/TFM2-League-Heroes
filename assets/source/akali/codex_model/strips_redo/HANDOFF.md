# 阿卡丽 A40 动作条交接

交付 10 张动作条与原样保留的待机条，共 64 个有效帧，其中动作帧 58 个；不是 58 张互不重复的原画。没有修改或导入游戏目录。

## 文件

- 根目录 `akali_*.png`：游戏用透明 8 倍图，每格 768×768。
- `native/`：对应 1 倍图，每格 96×96。
- `manifest.json`：每帧格子、时长、出手帧/tick、pivot、bbox、头部及原画来源；坐标从 0 开始，帧号从 1 开始，矩形为 x/y/宽/高。
- `preview.html`：离线动画播放器，按 manifest 毫秒时长播放，可暂停、逐帧和显示站位点；放大为最近邻。
- `previews/`：逐帧联系表、GIF 和 APNG；GIF 只能用 10ms 单位，因此 run 使用 100/110ms 交替，周期仍为 840ms。APNG 和 manifest 保留每帧 105ms。
- `design/`：原定稿、色板、头部及闭眼变体。
- `sources/`：实际参与最终合成的原始生成图；不能直接作为游戏素材。索引记录 SHA256 和对应提示词。
- `generation_prompts.json`：初始完整提示词及修复提示词，标明采用/弃用。`INPUT_REQUIREMENTS.md` 保留输入需求。

## 生成与整理

使用内置 image_gen.imagegen 生成身体动作，再按包内允许的流程提取角色、最近邻缩放、二值化透明、吸附定稿色板、贴头和放回原格子。身体吸色时排除 #D46A0A，琥珀色只通过复制头部恢复。原版渲染为镜像，修复时以近侧臂持苦无、远侧臂持镰刀为准。

每张初始提示词见 `initial_jobs.<动作>.prompt`，附图见对应 refs。run 最终采用 `redo_run_fix`；attack_p 第 1–2 帧采用 `redo_attack_p_windup`；突进共用原画采用 `redo_dash_correct`；投掷出手采用 `redo_throw_release`。逐帧精确来源见 manifest 的 art_source，原始图与提示词的关系见 sources/index.json。

## 已验证

- 11 张最终图均为严格 8×8 纯色方块，仅使用定稿 18 色的子集；透明度只有 0/255。
- 待机图与输入文件字节一致；所有帧的时长和 pivot 与输入 JSON 一致。空格透明。
- 一般帧不超过 native 第 81 行；死亡第 6–8 帧不超过第 83 行。
- 头外琥珀色像素为 0。除死亡末两帧外，所有头部不透明像素与定稿头/规定闭眼变体逐格相同。
- run 头相对 pivot 横向偏移固定为 -8，头顶部仅在第 47/48 行起伏。
- 已查看最终逐帧联系表；详细机器检查见 validation.json。

## 共用姿势及未完全达到的部分

为纠正镜像造成的换手和遗漏武器，部分原始生成帧被替换；最终动作不是逐帧完全照搬参考渲染。

- 除 run/dead 外，各动作最后一帧使用定稿待机姿势并按 pivot 平移；idle 六帧沿用输入。
- skill 第 2–3 帧共用蓄力原画，第 4–5 帧共用投掷出手原画。skill2 第 1/3 帧共用蹲姿，第 5 帧共用上述投掷原画。
- skill2_dash 第 1/3 帧共用突进姿势；第 4 帧用 skill 的举苦无姿势表示上挑，完整的上挑挥动轨迹没有逐帧展开。
- ult/ult2 使用同一组三张修正握持关系的突进原画，ult2 第 2/3 帧共用原画；ult 第 4 帧借用强化普攻抬镰刀姿势。
- 死亡第 1 帧用受击身体加睁眼定稿头；最后两帧保留生成的倒地头部并限色，符合输入允许的贴头例外。
- 突进身体前倾和伸臂幅度较参考保守，部分苦无为斜向；R2 未完全达到“身体近水平、苦无臂完全前伸”。投掷出手采用较低弓步。头部保持直立以保留定稿眼睛，并未逐帧匹配参考倾角。
- 手臂每处至少 3 格宽、所有材质恰为 2–3 色阶及每个站姿严格同高，未作为通过项；细小斜向肢体仍可能窄于目标。头部一致不代表身体形状逐格等同定稿。
- 尚未执行游戏导入、BOB 接缝适配、头像截取或引擎内出手触发测试。出手帧/tick 是按输入保留的元数据，不能视为已验证游戏伤害与画面同步。

## 导入建议

先用 preview.html 核对手感，再由负责游戏工程的流程导入根目录或 native 中对应版本，避免重复放大。按原需求接入待机 BOB 和 EYES=#D46A0A，并在游戏内确认释放时机、血条遮挡与头像裁切；不要把 sources 原图导入。
