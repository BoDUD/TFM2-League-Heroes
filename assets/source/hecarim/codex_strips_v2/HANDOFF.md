# 赫卡里姆逐帧重画交接

49 张独立 PNG 已全部交齐。run_2–7 保持本轮原稿，剩余 42 帧沿用同一生图提示、定稿与各帧骨架参考，另外参考旧稿和原版动作理解姿势。run_1 以 run_2 为直接参考重新绘制，调整了先前偏小的体型。使用内置 imagegen，每帧单独生成，交付 PNG 保留原始输出，供用户按格子读回整理。

## 最终文件

run_1 的偏小稿和过度放大尝试保留在 raw/。最终稿见根目录 run_1.png；大小对比见 previews/run1-scale-comparison.png。

死亡第 3 帧补强了两条后腿支撑、两条前腿抬起的人立姿势；第 7 帧以第 8 帧的侧躺姿势重画，强化头与身体贴地的衔接，尾巴比第 8 帧更大。初稿保留在 raw/dead_3_initial.png 和 raw/dead_7_initial.png。

## 读回时重点核对

- 各帧画布中的落脚高度和身体位置仍有漂移，尤其 run_1，与骨架一起读回时需要统一站位和落脚线。
- attack_1 的戟比骨架更竖直，较早进入举戟阶段；若严格保留原动作节奏，可调整初始戟角度。
- dead_4 扭身时的尾巴偏向画面右侧，和骨架里的尾巴位置有差异，需要核对这一段的尾巴过渡。

按用户最新要求，本轮交付原始重画稿，不以生产规格检查作为交付条件。实际画布尺寸、文件哈希和原始帧时长记录在 manifest.json；确认 49 个帧名完整，并核对根目录 PNG 与生图原稿字节一致。

## 预览与记录

review.html 可查看逐动作动画，左边是重画稿，右边是骨架；previews/ 内有 GIF、WebP 和逐帧对比图。预览缩放仅用于显示，交付 PNG 没有程序缩放、抽样或颜色量化。WebP 保留 frames.json 的毫秒时长；GIF 的时长精度为 10ms，85ms、55ms 等会取整。所有预览循环播放，包含死亡动作。

generation-prompts.json 保存实际提示词和参考图角色；generation-sources.json 保存选定生成器原稿来源。没有调用 CLI 或 API 回退路径。
