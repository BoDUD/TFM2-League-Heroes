# 悠米模型候选图交付

依据本次 yuumi_model_pack.zip，使用内置 image_gen 重新生成六种姿态、11 张候选图。它们尚未通过严格游戏模型规格。

## 文件

- 待机：`yuumi-model-A-1.png`、`yuumi-model-A-2.png`
- 侧面：`yuumi-model-S-1.png`、`yuumi-model-S-2.png`
- 前扑：`yuumi-model-L-1.png`、`yuumi-model-L-2.png`
- 扒竖书：`yuumi-model-R-1.png`、`yuumi-model-R-2.png`
- 附身趴书：`yuumi-model-B-1.png`、`yuumi-model-B-2.png`
- 合书：`yuumi-model-C-1.png`
- `raw/`：所选原始生成图，和交付 PNG 字节一致。
- `raw/rejected/`：未选尝试，仅作追溯，不应作为后续动作素材。
- `generation-prompts.txt`：全部实际提示词、参考路径、选用记录。
- `qa.json`：逐图尺寸、alpha 与 alpha128 包围盒检查。

## 检查结论

所选 11 张均为 1254×1254 RGBA PNG，具有真实透明通道。但每张均包含 256 档 alpha，存在半透明像素，**未通过仅 0/255 的硬 alpha 要求**。

提示词要求 A/S/L/R=22px、B=44px、C=30px，并做了针对性返工；生成器仍未严格落实全局等格、从原点对齐、48/21/25 格高度及固定地面线。**网格与位置规格未通过，不可直接按指定格长读回。**

A/L/B/C 的主要姿态可见；S 的书与身体仍偏 3/4，未达到纯侧面。R 已去掉初稿多余蓝球挂饰，但身体、尾巴及脸型与 A 的一致性仍需修整。双眼可见，但等大、等高及所有姿态共用同一张脸未严格成立。部分下沿/侧沿留白不足一格，详见 qa.json。

## 返工与选择

共生成 17 张，选用 11 张。A 的粗化返工底部留边不足，未选；B 的粗化返工改变毛色、脸型和触须颜色，未选；R 初稿增添多余蓝球挂饰，改用较简洁的返工稿；C 初稿为横向画布，改用正方形返工稿。

详细原画参考容易使生成器继续画细格；只保留粗目标又容易改变角色外观。后续应同时检查原始格子密度、角色一致性、硬 alpha、姿态和游戏实尺可读性，不能凭画布大小或文件体积判定完成。

本次没有用 Python 逐格绘画、缩放、重采样、阈值化或清理 alpha；代码只做复制、元数据检查和打包。未修改游戏、仓库或安装模组，未生成动作帧或进行游戏内 QA。本包可用于挑选造型，不能标记为游戏生产验收通过。
