根目录的 13 张 `norra-pose-*.png` 分别为：

| 文件后缀 | 关键姿势 |
|---|---|
| a_wind | 普攻起手，右手收回，左手持环后摆 |
| a_point | 普攻指向，右手向右上指，左手持环 |
| q_swirl | 双手在胸前聚拢，环在双手之间 |
| q_throw | 右手抛出，左手持环 |
| e_open | 左手举环，右手向外张开 |
| r_raise | 双手举起，脚离地 3 格 |
| r_cast | 落地下压 |
| run1 | 跑步接触帧，远脚在前 |
| run2 | 跑步收脚帧，近脚支撑 |
| run3 | 跑步接触帧，近脚在前 |
| run4 | 跑步收脚帧，远脚支撑 |
| d_fall | 后仰受击，双手空，金环脱手 |
| d_down | 坐倒，短腿前伸、双手后撑，环落在身前 |

- `pose-overview.png`：同一显示比例的 13 张总览，用于检查身份、姿势、环与脚的位置。
- `raw/norra-pose-*-raw.png`：最终选用的 13 张原始生成 PNG，未经处理，后续部件提取优先查阅它们。
- `raw/rejected/`：跑步第 3 帧前两次多手臂/多环版本、带多余飞行小粒子的死亡起始帧。仅供追溯，**不要用于动作集成**。
- `generation-prompts.txt`：全部 16 次实际提示词和生成工具返回的保存位置。
- `validation.json`：各图源尺寸、包围盒、输出尺寸、透明度、网格及底线检查数据。

## 输出处理与检查

13 张根目录 PNG 均为 1254×1254 RGBA，alpha 只有 0/255，网格从左上角以 14 px 对齐，程序检查每格内部色值一致。着地帧可见包围盒底边为 y=1176，悬空 r_raise 为 y=1134。run2/run4 的总轮廓比接触帧高一格，以保留收脚阶段的起伏。

生成器没有直接严格满足画布内的网格与尺寸定位。根目录文件对最终原稿进行了硬 alpha 清理、可见区域裁切、最近邻网格采样、14 倍整数放大和透明画布定位。这属于交付尺寸整理；没有用代码添加手脚、修补人物、替换头部或重画动作。原稿全部保留，缩回参考存在局部细节损失。

逐图目视检查了同一服饰身份、正面偏右朝向、脸部无遮挡、持环数量与死亡脱手状态。run3 的多手臂/双环错误已用图像生成工具修正；d_fall 的多余飞行小粒子已用同工具移除。总览已检查。

## 精确整合时需要保留的限制

这些文件是**动作姿势源图**。图像生成保留了同一角色的整体身份，但头部仍为模型重画，尚未逐格复制 `1_head.png`；帽沿、羽毛、眼镜和耳朵局部存在帧间差异。归一化按总轮廓定位，不等于已完成骨架像素注册。手臂约 13 格、腿约 10 格、金环约 7 格及头部 37×47 格的要求写入了生成提示词，未逐关节完成测量验收；不能把技术网格检查当作这些比例全部通过的证据。

本轮没有生成大门、魔法弹、球或纸页特效，没有制作待机/受击、动作中间帧、游戏图集或运行时文件。后续集成应以本轮包内的定稿头部锁定像素与调色板，并按骨架逐关节复核，再组织普攻、技能、跑步和死亡的时间序列。尚未进行游戏内播放验收。
