# 呲呲跑步腿部重画

## 改动

重画 8 帧跑步，使用内置 image_gen，8 张首稿加 7 次局部返修。上半身沿用既有造型参考；没有用代码逐格绘制腿、拼接腿或拉伸身体。

- run1、run2：亮的近侧腿在前，暗的远侧腿在后。
- run4、run5、run6、run7：暗的远侧腿在前，亮的近侧腿在后。
- run3：暗的远脚抬起，从亮的近腿后方经过；两脚横向差 1.5 格。
- run8：亮的近脚抬起，从暗的远腿前方经过；两脚横向差 1.0 格。
- 远侧腿加深为褐色、深紫色；run6 又作了一次整条远腿压暗。

## 核验

所有交付帧为 1254×1254，真透明 alpha 只有 0/255。交付版不缩放、不重采样，仅作硬 alpha 处理与整数 Y 平移，像素下边界对齐 y=1176；原始生成图保留在 raw/，没有改动。

八帧的前后腿顺序通过检查，两张交错帧的脚尖横向间距均小于 2 个名义 10 px 格。精确导入时序为包内给定的 [120,135,105,80,80,100,120,60] ms，总计 800 ms，见 manifest。GIF 容器使用 10 ms 时间单位，预览将 135/105 ms 分别取为 140/100 ms，仍保持 800 ms 循环。循环 GIF 和总览进行了预览缩小，单帧素材没有缩小。

## 未通过的严格项目

图像生成没有完全遵守绝对脚尖坐标与步幅。尽管已经按坐标提示、位置标记和局部箭头进行返修，实际绝对位置仍超出 feet.json 的 ±2 格要求；部分伸展帧的步幅大于目标。不能把“前后顺序、交错通过”误写为“所有脚尖坐标与步幅通过”。生成网格不是经验证的严格 10 px 网格；远腿色彩也不是逐像素只含要求的指定十六进制色。头和上半身保持参考造型，但不是八帧逐像素复制锁定。

## 文件

- zippy-run-run1.png … zippy-run-run8.png：8 个交付帧。
- raw/：15 张生成/局部编辑原稿，全部字节原样保存；选中版本见 manifest.json。
- generation-prompts.txt：实际提示词与参考路径；初次生成把定稿和头部放在同一张参考联系表上，以满足工具最多 5 张参考图的限制。
- manifest.json：选中原稿、整数平移、帧时长。
- expected-feet.json：输入 feet.json 原样复制，与实测值分开存放。
- validation.json：逐帧近远脚位置、目标误差、谁在前以及交错结果。
- run-preview.png：8 帧总览。
- feet-validation-preview.jpg：带实测标记的核验总览。
- run-cycle.gif：循环预览。

本轮未修改前一版动作包或特效包，也没有执行文档中给 Claude 的游戏导入或仓库修改步骤。
