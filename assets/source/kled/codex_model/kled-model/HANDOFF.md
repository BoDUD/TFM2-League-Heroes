# 克烈第 1 步：粗格模型候选稿

## 交付状态

本包为 image_gen 绘制的骑乘两稿 A-1/A-2、下马两稿 B-1/B-2，供挑选造型和后续像素母版整理。不是已经通过严格像素格网验收的最终模型，也未进入游戏安装资源。

造型保持第 0 步的青绿红帽、钢尖刺、大尖耳、米白胡子、一只瞎眼、狂笑尖牙；骑乘稿保留橙黄鳞片、紫腹、青蓝头刺、黄绿大眼、细腿和金星护腿。第一轮使用细节原稿作主参考，结果仍太细；第二轮改以 2_target 为编辑主图、4_head 为身份参考、已有英雄为风格参考，得到更粗的方块造型。最终四张均取自第二轮。第一轮只保存在 raw，不作为最终候选。

## 文件与调用映射

- kled-A-1.png ← raw/modelRetryA1.png
- kled-A-2.png ← raw/modelRetryA2.png
- kled-B-1.png ← raw/modelRetryB1.png
- kled-B-2.png ← raw/modelRetryB2.png
- raw/modelA1.png、modelA2.png、modelB1.png、modelB2.png：第一轮，未采用，原因是密度过细或画布不符。
- generation-prompts.txt：完整实际提示词，first_A/B 各调用两次，revised_A/B 各调用两次。
- qa.json：最终四稿原始尺寸、可见框、alpha 和严格格网测量。
- check-kled-model.py：只读检查脚本，不绘画、不处理图片。

所有 PNG 都是工具返回文件的原样副本；没有用程序逐格绘图，没有平滑缩小、最近邻缩小、阈值改 alpha 或强行凑格数。raw 保留全部 8 次成功生成的原始文件。

## 未通过项，制作动画前必须处理

1. 原始输出带有多级 alpha；不能当作 alpha 仅 0/255 的正式帧。
2. 视觉方块已经加粗，但没有严格落在从 (0,0) 起的 14px 格网；不能直接按 14px 一格读取。qa.json 的 uniform_cell_fraction 为严格整块同色检查，数值低说明它不是数学意义上的整格图，不等同于视觉质量评分。
3. 帽尖、眼线和脚底位置仍有生成偏差；真实可见范围以 qa.json 的 alpha≥128 框为准。A 必须整理到 80 行、B 到 58 行后再进入 PPU/动作制作，不能以画布尺寸代替行数证明。
4. 四稿的头部是同一设计，但并非像素完全相同的头。选稿后应以选中 A 的头作为唯一母版，统一 B 和所有动作；本次未擅自替用户选稿并贴头。
5. 瞎眼与好眼是否同高、各 2×2，牙齿 1×2，斯嘎尔眼 3×3，描边连续 1 格，都没有通过逐格最终验收；尤其还需精修好眼与粉色疤痕。

## 下一制作阶段

先从骑乘/下马各挑一稿，再测量 raw 实际格子；按目标行数整理像素母版、共用头部和武器，复核面部后才生成 hd/idle.png 与 hd/foot.png。计划 PPU 2.0，但本包没有改动主包数据、动画或 DLL，也没有游戏内截图验收证据。
