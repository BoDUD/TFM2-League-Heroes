# 雷克赛技能特效交付

## 内容

共 18 组特效、86 帧，均由内置 image_gen 生成原稿，再按目标游戏像素网格转换；没有用代码绘制特效形状。范围覆盖普攻、女王之怒、猎物搜寻、狂野之噬、遁地/破土、回血、怒气满、虚空猛冲、猎物标记、隧道与隧道崩塌。

- 根目录 `reksai_fx_*.png`：18 张 8 倍最近邻放大横向图条。
- `pixel_1x/`：18 张原尺寸游戏像素图条，导入时使用这一份。
- `raw/`：18 张最终采用的 image_gen 原稿，未修改文件内容；`raw/rejected/` 保留带柔光背景而被替换的原稿。
- `preview.png`：全部特效的静态帧总览。
- `animation-preview.gif`：动态检查预览，110 ms/帧；不是游戏的最终播放速度配置。
- `manifest.json`：帧数、单帧尺寸、图条尺寸、对称方向、循环标记、绑定参考、调色板、逐帧检查及原稿哈希。
- `verification.json`：独立导出检查结果。
- `generation-prompts.txt`、`generation-specs.json`：实际请求提示词和重生成记录。

## 使用方式

每组是一行，从左到右切帧。按 manifest 的 `frame_size_1x` 切 `pixel_1x/` 内文件；不能直接拿原稿按等宽横条切，因为原稿使用 2×2 或 3×2 布局，五帧原稿右下格为空。原稿采取两行布局以减少超长画布生成时的帧细节损失，交付图条已重新排成要求的单行。

`q2_shot` 朝右，每帧严格上下对称；其他 17 组每帧严格左右对称。帧数、尺寸及绑定参考详见 manifest。游戏显示尺寸与素材画布尺寸并不相同，绑定参考中保留了包内的游戏显示尺寸。

## 转换与检查

先按原稿帧格和目标逻辑网格分区，源样本 alpha ≥128 才视为可见；近黑背景（RGB 最大分量 <20）视为透明。可见样本映射到指定调色板，汇总镜像位置的颜色票数，每个目标像素取可见颜色的多数色。为保留末帧小火花，可见覆盖阈值采用 25%；因此这是“可见颜色多数票”，**不是将透明区域也参与票数的严格 RGBA 多数票**。最终 alpha 只有 0 和255。

从原稿取色后，对原稿分行串入下一帧的少量边界残线进行了清理：去除顶部两行内、独立且宽高比至少8的长条连通域；隧道崩塌末两帧还去除了顶部三行内宽至少3格的独立上一行残片。没有新增形状。清理像素数记录在 manifest 中。8 倍图仅使用最近邻放大。

独立检查通过：18 个预期文件齐全、共86帧；所有单帧尺寸正确；全部硬透明且逐帧严格对称；全部可见颜色属于相应调色板；8 倍图与1倍图完全对应；原稿哈希一致；没有空白帧。

## 实际限制

生成原稿的尺寸、方块步长、帧间造型和亮度没有严格遵守提示词。导出修正了尺寸、硬透明与对称性，但不能等同于通过游戏内艺术验收。部分消散、纯泥土或较暗的循环阶段没有白/淡色亮芯；`q2_shot` 第2帧、`r_mark` 第1帧等也应在暗底游戏环境中确认亮度。每帧 `has_bright_core` 检查写在 manifest 中。

实际轮廓宽度、站位点、环的透视及无遮挡范围需要集成时对照动作再检查；本次没有自动保证所有光形均无最深色轮廓，也没有验证大招爪痕的细线数量或循环接缝完全符合参考。GIF 是视觉预览，播放帧时长需要游戏工程配置。

本次完成素材制作与导出，没有改动游戏工程、绑定技能、制作游戏图集或发布。包内官方参考贴图只作本地形状参考，未放入交付包。
