# 妮蔻附加包（测试版 v0.2.0，可选）

**不装这个附加包，主包里的妮蔻也是完整的**：普攻和 W 两生花影的第三下强化、Q 盛开花种（炸到英雄再盛开两次）、E 缠结倒刺、
R 怒放，以及连招 E → Q、R → Q 都在主包数据里。主包是纯数据：**数据换不了外形**，所以主包的妮蔻没有被动。这个附加包用原生代码
做她的被动「天生幻魅」（用户 2026-10-21 选「做，附加包」），0.2.0 起还有 W 两生花影的主动和它的分身（用户 2026-11-14 问她有没有
W 的分身，答「加」）。

| | 主包（纯数据） | 装了附加包 |
|---|---|---|
| 天生幻魅 | 没有 | 脱战 2 秒后**整个身体画成最近的友方英雄**（站、跑、出招、挨打都用他的图）；放技能、被控（击飞、晕眩、禁锢、嘲讽、恐惧、魅惑、强制位移）、假扮以来挨了她 35% 最大生命的伤害、或假扮的队友阵亡时现形；**放技能现形后 4 秒 20% 法术穿透**（英雄联盟的数值）；现形 6 秒后才能再变 |
| W 两生花影的主动 | 没有（三个技能位放 Q / E / R，W 只有并进普攻的被动） | 0.2.0：**附加包自己放**——1 秒内挨了她 15% 最大生命的伤害、90000 内有敌方英雄时，她隐身 0.5 秒、移速 +30% 3 秒，脚下留下一个**真的分身**（`spawn_unit` 的单位，也叫 `league_neeko`：她的图、她的高清帧；她正假扮着，分身就是同一个样子），活 3 秒，会走、会追人、不打人，挨打 0.5 秒后消失；冷却 14 秒，从分身没了算起（英雄联盟的数值，见最后一节） |

## 怎么做的

- `mod.override_info` 把主包的妮蔻换成 `override/` 里的副本（`make_override.py` 用 `tools/kit/build_neeko.py` 的 `native=1` 生成，
  主包的妮蔻改了就重跑）：数据和主包一样，多了被动 `league_neeko:glamour`（数字在 `passive.params`）和变身 / 现形的画面
  `league_neeko_p_poof`；普攻的说明开头加【附加包】、写上被动。
- **被动**（模拟里）：每 tick 看技能冷却有没有从 0 跳上去（league_yuumi 的做法：Q、E、R 都是伤害技能）、身上有没有打破伪装的控制、
  `on_damaged` 累计假扮以来挨的伤害；变身挑附近最近的、活着的、`souls.rs` 动作表里有的友方英雄（别的 mod 的英雄名字对不上图会让游戏
  panic，不变）。法术穿透是原生加的 buff `league_neeko_p_pen`（`magic_resistance_penetration`）。
- **外形**（`src/view.rs`，佛耶戈附身 0.1.7 的做法）：屏幕放的那场模拟几秒钟就把整局跑完，屏幕几分钟后才放到，显示世界也收不到原生加的
  buff，所以被动在屏幕放的那场模拟（ClientMatchView / 观战 / 回放）里记下每次变身和现形的 tick、队友的英雄 id；`game_places::hook::add`
  的显示钩子按屏幕上的比赛时钟（`game_places::clock`）把名字是 `league_neeko` 的画面实体的身体资源名（+0x50）换成那名队友显示实体的、
  正在播的动作名换成他图里有的（`hd_` / `lo_` 前缀照留：skill2 → skill → attack → idle，ult / ult_b → ult …），时段外写回她自己的。
- **时钟**：游戏每个 mod 只有一个客户端扩展槽，league_addons 里归佛耶戈的读时钟扩展；它现在也喂 `game_places::clock`，妮蔻读它。
  单独装这个附加包的 DLL 时，本包自己挂一个只喂时钟的扩展（`ClockFeed`）。
- 动作表是佛耶戈附加包的 `league_viego_soul/src/souls.rs`（`#[path]` 共用，由它的 `make_override.py` 生成）：表里没有的新英雄不会被假扮。

## 在游戏里测

- 日志：`%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_neeko.log`（每次启动游戏重写，上一次的在 `.prev.log`）。
  `DISGUISE n as <英雄>`、`REVEAL from <英雄> (cast / crowd control / hit through / the ally fell / dead)` 是模拟里的变身和现形；
  `Neeko #<key>: drawn as <资源名>` 是屏幕上她被画成谁。
- 看她开局 2 秒左右变成身边的队友、放技能时变回妮蔻（带一下变身的画面和音效），6 秒后又变。
- W 的分身（0.2.0）：挨了一大口时她半透明一下、身上一团烟，脚下多出一个一模一样的她（假扮着就是那名队友）跑开，挨打后一团烟
  没了；日志是 `SPLIT` 开头的行（见最后一节）。

## 0.1.12：日志每种行整个启动一个计数（2026-11-08）

11-08 夜里的日志一次启动 657 KB：`DISGUISE` 3195 行、`REVEAL` 3184、`SPAWN` 288（每行都带整张参数表）。条数限的是每个妮蔻每局 200 行，一场预演
才 ~51 行，等于不限，服务器每次启动又跑几百场预演。现在和 league_yasuo_wall 0.1.2 一样每种行整个启动一个计数：预演先记 40 行、之后每 100 行记一行，
你看的那场每行都记，行末多一个 `#k`；参数只写在一次启动的第一行 `SPAWN` 里。玩法和外形不变。

## 0.2.0：W 两生花影的分身（2026-11-14）

她的资料页原来写着「W 的分身在三个技能位里放不下，没有做」：TFM2 只有三个技能位，Q / E / R 占满了，W 的被动（每第三下普攻）并进了
普攻。用户问妮蔻有没有 W 的分身，答「加」。召唤物这一轮（「召唤物的全做啊 … 都做完了装进去了再测」）有了 `spawn_unit`，W 的主动
现在由附加包的被动自己判断、自己放（`src/split.rs`）。**普攻和三个技能位一个字节没改**：副本的数据和 0.1.x 一样，只有普攻的说明多
一句（五种语言；为了不超过详情面板的长度，天生幻魅那句也略缩了几个字）。

英雄联盟（wiki 现行页面，V26.20）：她和分身一起隐身 0.5 秒，两人移速 +20/25/30/35/40% 3 秒；分身照她当时的样子（假扮着就是那个
样子，而且不会现形），活 3 秒，挨打 0.5 秒后提前消失，前 0.5 秒敌人选不中；冷却 16/15/14/13/12 秒，V26.05 起从分身没了才开始算。
这里取中间那一级（她的 E 也是：英雄联盟 12-10 秒 → 11 秒）：

| | 数值 |
|---|---|
| 什么时候放 | 60 tick（1 秒）里挨的伤害到她最大生命的 15%，90000（她 E 的射程）内有活着的敌方英雄；W 好了、她没被控（击飞、晕眩、嘲讽、恐惧、魅惑、强制位移、沉默；禁锢不算）、不在 R 的蓄力和跃起里（R 放出后 80 tick） |
| 她 | 隐身 30 tick（`entity_set_invisible`），移速 +30% 180 tick（buff `league_neeko_w_go`），身上一团变身的烟（`league_neeko_p_poof`）和变身的声音 |
| 分身 | `spawn_unit` 在她脚下生成：名字 `league_neeko`（按她自己的图画，league.dll 的高清帧也按名字认，和她一样大），活 180 tick，攻击 0（英雄联盟的分身不打人），普攻的距离、间隔照她的（55000，每 92 tick），移速、护甲、魔抗照她的，生命上限照她的、当前生命设成她当时的；也隐身到施放后 30 tick、一样加速；引擎管着它走、追人、挨打 |
| 挨打以后 | 生命第一次往下掉后 30 tick 放逐到时间结束（`entity_banish`：看不见、打不到、不能动——API 没有让单位消失的接口，纳亚菲利的狗也这么做），原地一团烟和现形的声音 |
| 冷却 | 840 tick，从分身消失、被打死或到时间算起 |

- **原生效果** `league_neeko:split`：被动决定放 W 的那一拍排它，下一拍放；排不进就被动当场放。生成后在她身上挂几 tick 的
  `league_neeko_w_uid:<单位 id>`，被动接手；没给单位就挂 `league_neeko_w_none`。
- **新单位头两拍读不准**（游戏 0.7.2 的预模拟日志：悟空的分身生成后一拍读到 `hp 1851/1 attack 1 def 1 mr 1 speed 1`，那时设的
  1 血再一拍又成了 1851/1851）：被动至少等交接后一拍、等它的最大生命读出来，才给它设生命、隐身、加速。
- **她的样子**：她正假扮着时，被动在显示钩子里替分身记下同一名队友（`view::note_on`，按分身自己的实体号），分身画成那名队友，
  她现形了它也不变，到它没了为止。显示钩子按实体号认，两个叫 `league_neeko` 的实体互不影响：分身只有被记下时才换样子，原资源名
  各记各的；记满 64 条时先丢这一帧不在画面上的（以前丢最老的一条：一局里几十个分身时可能丢掉她自己的那条，现形后就一直画成
  队友）。判断都在 `view::plan`（纯计算，单元测试）。她挑队友假扮时只看英雄、从不挑 `league_neeko`，所以不会扮成自己的分身；
  W 不是伤害技能，不打破假扮（英雄联盟也是）。
- **引擎要是把被动也给了分身**（它和她同名，不知道会不会）：被动认出自己挂在召唤物上（`EntityKindV1::Summon`），什么都不做，日志
  写一行 `SPAWN: her passive given to a unit`。
- **退路**：宿主没有 `spawn_unit`、生成失败、给的 id 6 tick 内读不成单位——没有分身，她的隐身和加速照旧（施放那一刻就给了），冷却
  照算；日志旁边的 `league_neeko.cfg` 写 `unit=off`：整个 W 都不放（和 0.1.x 一模一样）。另外两个开关同萨科的：`still=1`（分身移速
  1）、`name=<名字>`（换一个单位名试）。
- 她先死了：挨过打、还没消失的分身当场放逐；没挨过的由引擎管着到时间。

日志（`league_neeko.log`）：第二行 `SPLIT: Shapesplitter's active (W) is the add-on's own: ... - ON`；每口大伤害一行 `SPLIT #n CAST`
（放了：伤害占她最大生命多少、多少来自英雄、最近的敌方英雄）或 `SPLIT HOLD`（没放和原因：冷却还剩几 tick、被控、R、身边没有英雄、
上一个分身还在、`unit=off`）；`SPLIT SPAWN`（她的隐身设没设上、单位的全部数字）/ `SPAWN FAILED` / `NONE` / `LOST`；每个分身 `LOOK`
（读回来的名字、种类、能不能选中、生命、属性；生命、隐身设没设上；画成谁）/ `DRESS`（一拍后的生命、加速 buff 在不在）/ 每秒一行
（走了多远、离她多远、身边的敌人）/ `HURT` / `FADE`（放逐成没成）/ `OVER` / `WAKE` / `ORPHAN`；显示钩子的
`world ... Neeko's clone #<key>: drawn as <资源名>` 是屏幕上分身画成谁。

只能在游戏里看的：隐身和放逐的单位在屏幕上怎么画（游戏的隐身画成半透明）、0 伤害的普攻显示什么、引擎的单位 AI 把它带到哪（API
没有给单位下命令的接口：它追最近的敌人，英雄联盟里分身朝她指的方向跑）、一局放几次（数 `CAST` / `HOLD` 行，太多太少就调 15%）、
分身画成队友时显示世界里它的实体号是不是它的模拟实体号。
