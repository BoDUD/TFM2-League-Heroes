# 普朗克附加包（测试版 v0.3.0）

0.3.0（2026-11-12）：**银蛇币**——枪火谈判击杀掠夺银蛇币和金币，回泉水时按局势给加农炮幕买升级（见下面的表和 [0.3.0](#030银蛇币2026-11-12)）。

0.2.2（2026-11-05）：待命式大招没用掉时的冷却退还从来没生效过：n tick 的待命标记只有 n - 1 tick 看得见（经典 SDK 探针 lr1105/fix_j：n - 1 之前 148/148 次看得见，第 n tick 0 次），退还在窗口最后一 tick 读它时已经没了，所以每次待命过期都要等完整冷却（塞恩追踪：过期到再待命 3558 tick，改读后 877）。现在在窗口结束前 3 tick 读（`tools/kit/build_gangplank.py`），副本跟着主包重新生成；DLL 没变。看 `league_ult_press.log` 的 `R ARMED … refunded (not used)`。

主包 `league` 保持纯数据。用户选了技能方案 A（「技能方案按 A 做」，带扩展包）。这个附加包用原生代码做主包数据做不到的三件事：
**坏血病疗法真的解除控制**、**残血也吃橘子**、**火药桶按距离连锁**，v0.2.0 起还有**火药桶充能**和**三连桶**，v0.3.0 起还有**银蛇币**。画面、声音、伤害仍然是主包里的那一套（附加包只判断、挂标记）：

| | 主包（不装附加包） | 装了附加包 |
|---|---|---|
| 坏血病疗法（W） | 3 级起被控制或被围攻时自动吃橘子：回血、免控 1 秒；已经在身上的控制要等它自己结束 | 同上，另外吃下去的那个 tick **清掉他身上的硬控**（英雄联盟：W 解除控制）；**生命低于 40%** 也会吃 |
| 火药桶连锁（E） | 一个桶炸开，别的点燃的桶边有敌人就跟着炸（不管多远）；桶边没人就不炸 | 两个桶相距不超过 `e_chain`（70000）才连锁；桶边有敌人照样由数据炸，**桶边没人也空炸**（画面、声音、刷新烈火审讯和加速都有），空炸的桶接着往下连 |

| 银蛇币（Q + R） | 没有 | 枪火谈判**打死**目标掠夺银蛇币（40–80 枚，随比赛时间）和 3–7 金币；**回泉水**时每攒够 500 枚**按局势**给加农炮幕买一个升级：**死神的女儿**（开始 0.5 秒后中间砸一颗大炮弹：一波伤害的 300% 真实伤害、减速 60%）、**开火**（同样时间打 18 波）、**鼓舞士气**（炮幕里的友方英雄加速 40%，结束后再 2 秒）；技能栏的层数格显示手里的银蛇币 |

## 怎么做的

- **清控**：副本里吃橘子时给他挂 2 tick 的 `league_gangplank_w_now`；本包看到它出现、他身上又有硬控（击飞、眩晕、禁锢、嘲讽、恐惧、魅惑、
  强制位移——游戏 0.6.4 把施法动作也记成一种控制，所以不用 `cc_count() > 0`），就 `entity_clear_cc`。清控会连正在放的施法动作一起清掉，
  所以两个副本里吃橘子的动作、声音和回血都放在决定之后 2 tick；免控在决定时就挂上，这 2 tick 里不会再被控。
- **残血**：他活着、生命低于最大值的 `w_low`% 时一直挂着 `league_gangplank_w_low`，数据的自检（每 12 tick）看到它也会吃（3 级起、W 不在冷却）。
- **连锁**：桶落地（`k<s>_live` 出现）时，他新出现的两个区域落在同一点，那就是桶的位置（`ProjectileInfoV1` 没有名字）。一个桶炸开后一 tick
  数据挂 `k<s>_now`；另一个桶已点燃、两桶相距不超过 `e_chain` 时本包挂 3 tick 的 `k<o>_cn`，副本的触发区读它（主包读的是另一个桶的爆炸，
  不量距离），桶边有敌人下一 tick 就炸。桶边 `e_r` + 20000 以内一个敌方单位都没有时本包空炸：挂 `k<o>_blew`（数据的下一次贴图画爆炸）、
  摘掉 `k<o>_live` / `k<o>_ripe`，摘 `p_cd`、给被动加速（和数据的爆炸一样）。
- **充能**：本包自己记手里几个桶（E 解锁时 1 个，最多 `e_stock`，每过一轮 E 的冷却 `cooltime` 回一个）；看到 E 的冷却跳上去就是扔了一个，
  手里还有桶就用 `entity_reduce_cooldown` 把冷却减到只剩 `e_gap`（需要游戏的 ABI 10）。三连桶补的桶也从手里扣。手里没桶时 E 的冷却
  照常走完（和回一个桶的时间一样长）。
- **三连桶**：`q_fire`（枪火谈判打中时数据挂在他身上）出现的那个 tick，看点燃的桶（`k<s>_ripe`）和 `e_range` 内的敌方英雄。第三个
  桶由本包画（落地、点燃、爆炸的画面和声音都是主包的），伤害、无视护甲（1 tick 的 `e_pen`）、减速照数据的桶。先炸的桶边有敌人时
  数据会因为 `q_fire` 自己炸它，没人由本包空炸；另一个桶由连锁带上。
- **银蛇币**（0.3.0）：
  - **掠夺**：副本的枪火谈判打中时先给他挂 `k_q`，目标还活着就摘掉（league_draven 的击杀判断）；4 tick 后还挂着就是打死了，挂 3 tick 的
    `q_kill`、头顶冒一枚银币。本包看到 `q_kill` 出现就加 `plunder` 枚银蛇币、`plunder_gold` 金币（src/lib.rs）（`player_add_gold`）：英雄联盟
    4–8 枚、3–7 金币（随枪火谈判的等级）。这里的等级跟比赛时钟走（每 `sv_rank_t` = 3 分钟一级），银蛇币是英雄联盟的 `sv_scale`% = 10 倍
    （经典引擎里他一局的枪火谈判击杀只有英雄联盟的十分之一左右，见 0.3.0）。
  - **买**：他在泉水（新的身子第一次站的地方 `sv_home` = 60000 以内：出生、复活；原地复活不算）、手里够 `sv_cost` = 500 枚，就按局势挑一个
    （`choose`）：死神的女儿 2 分，人头落后 3 个以上再加 2、对面平均护甲是他这一队的 1.25 倍以上再加 1；开火 2 分，领先 3 个以上再加 2、
    炮幕平均罩住 2 个以上敌方英雄再加 1；鼓舞士气 1 分，炮幕平均罩住 1 个以上己方英雄再加 2（炮幕至少落过 2 次才看罩住几个）。分高的先买，
    一样高按死神的女儿、开火、鼓舞士气。
  - **升级**：买过的升级是他身上的旗子 `league_gangplank_up_dd` / `up_faw` / `up_rm`（死了复活后补回），副本的加农炮幕读它。炮幕落地时副本
    挂 `r_land`，给炮幕里的敌方、己方英雄各挂 3 tick 的 `r_in` / `r_ally`，本包下一 tick 数（选升级用）。塞拉斯偷到的、佛耶戈附身用的
    加农炮幕是主包那份，没有升级。
  - **面板的数**：手里的银蛇币挂成 `league_gangplank_sv_<n>`，league.dll（0.9.36 起）的技能栏层数格按梯子规则读出 n，旁边是大招的图标
    （`tools/kit/stack_nums.py`，只写进本包的副本：主包的普朗克没有银蛇币）。
  - **画面**：`league/effects/league_gangplank_sv`（主包 0.341.0 起，`tools/art/gangplank_sv_fx.py` 画）：大炮弹的落点圈、下落、落地爆炸
    （火药桶的爆炸加一圈金色冲击波）、鼓舞士气脚下的金圈、掠夺时头顶的银币。
- 本包**不按任何技能键**（不会在技能没解锁时按键，解锁总闸也不涉及）。

参数写在英雄数据的 `passive.params`（`w_low`、`e_chain`、`e_r`、`e_link`、`p_ms`、`p_ms_t`、`e_stock`、`e_gap`、三连桶的 `e_*`，
银蛇币的 `sv_scale`、`sv_rank_t`、`sv_cost`、`sv_gold`、`sv_home`），由 `make_override.py` 从 `tools/kit/build_gangplank.py` 的参数表 `P`
写入；升级的数值（`r_faw`、`r_dd_*`、`r_rm_*`）在数据里。

## 在游戏里测

1. 主包（League of Legends Heroes 0.145 以上；技能栏显示银蛇币要 0.341.0 以上）要装着并启用。
2. 用附加包合集 `league_addons`（里面已经包含本包），或者把整个 `league_gangplank` 文件夹放进 `<游戏目录>\mods\`
   （要有 `league_gangplank.dll`、`mod.mod_info`、`mod.override_info`、`override\`、`text\`）。
3. 进游戏，在 MOD 菜单里启用它（含代码的 mod 会弹一次确认），确认排在主包后面，重启游戏。
4. 看普朗克的普攻说明：开头是「【附加包】」就说明换上了（枪火谈判、加农炮幕的说明里有银蛇币）。
5. 日志在 `%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_gangplank.log`，每次启动游戏重写（上一次的留在 `.prev.log`）：
   - `SPAWN`：出生；`CLEANSE`：吃橘子清掉了几个控制；`LOW`：生命低于线、挂上 `w_low`；`KEG`：桶的位置找到了；`KEG?`：桶落地后没找到
     它的两个区域；`CHAIN`：连锁（交给数据——带离桶最近的敌人多远，或本包空炸）；`CHAIN LATE`：交给数据的桶 4 tick 后还亮着，本包空炸（0.2.3）；`STOCK`：扔了一个桶、手里还剩几个；`TRIPLE`：三连桶（哪两个桶、
     第三个扔给谁）；`THIRD`：第三个桶炸开，炸到几个人。
   - 银蛇币（0.3.0）：`HOME`：他的泉水在哪；`PLUNDER`：枪火谈判打死一个，几级、加了几枚、手里多少、加了几金币；`BARRAGE`：炮幕落地罩住
     几个敌方、己方英雄；`BUY`：在泉水买了哪个升级、为什么（分数、人头差、对面护甲倍数、炮幕平均罩住几个人）、还剩几枚。

## 开发

- `python addons/league_gangplank/make_override.py`：从参数表重新生成 `override/` 和 `text/`（先核对主包的普朗克和参数表一致）。
  主包的普朗克改了以后要重跑。
- 在 `addons/` 下 `cargo test --release -p league_gangplank`：单元测试（参数、残血线、连锁距离、从新区域里认出桶、银蛇币的掠夺和按局势选升级）。
- 在 `addons/` 下 `cargo build --release -p league_gangplank`（Windows）得到 `target/release/league_gangplank.dll`；`league_addons`
  合集也会编进本包。工作区路径很长时用 `CARGO_TARGET_DIR` 指一个短路径（链接器打不开长路径的临时文件）。
- 经典 SDK 的模拟器跑不了原生被动，本包只做了单元测试，要在游戏里看日志确认。升级的强度可以在模拟器里看：把副本里的 `SwitchByBuff up_*` 换成买了 / 没买的那一支（见 0.3.0）。
- `python tools/art/gangplank_sv_fx.py`：重画银蛇币的画面（`--check` 核对，`--preview x.gif` 看一段假的炮幕）。

## 0.2.1：他死后火药桶不再连炸（2026-11-02）

桶的引爆区和画面链是桶落地时开的，他死了也照样跑完；死人身上的标记冻住：Q 打中后 1 秒或连锁时他死掉，熟桶每 tick 炸一次；桶炸后 11 tick 里他死掉，画面链每 10 tick 再放一次爆炸和声音（正式游戏里死人的延时效果继续跑）。两处都先问他还活着没有（`alive()`），改在 `tools/kit/build_gangplank.py`，主包和本包的副本一起（查茂凯树苗「死后无限音效」时一起查出来的）。

## 0.2.2：桶终于会连锁了（2026-11-05）

11-04 一整天的日志：`KEG` 记到 #3500、`TRIPLE` 7 次，`CHAIN` 一次都没有（0.1.0 起就这样）。原因：`on_update` 先跑 `track()` 再跑 `chain()`，而数据的爆炸在同一个 Delayed 里摘掉 `k<s>_live`、挂上 `k<s>_now`——`track()` 看到 live 没了就把这个桶的位置忘掉，紧接着的 `chain()` 读到的位置是 None，什么都连不上（三连桶由本包空炸的那一半能连，数据炸的那一半不能）。现在先 `chain()` 再 `track()`：炸开的桶的位置先读出来（`blown`），再忘（`forget`）。加了单元测试（一 tick 内 live 灭、now 起）。下一局看 `CHAIN`：数据炸开的桶边上点燃的桶该跟着炸。

## 0.2.3：交给数据的桶没炸就本包炸（2026-11-06）

11-06 的日志：`CHAIN` 41 + 42 次，连锁本身好了，但「left to the data (an enemy beside it)」的桶有时一直不炸——m=2848 的 keg 3 t=20202 交给数据，t=20246 另一个桶炸开时它还亮着、又被连锁一次。原因：本包判「桶边有人」量的是 `e_r` + 20000（`EMPTY_MARGIN`），数据的触发区只量 `e_r`（30000）以内的单位；人站在两者之间，本包不空炸、数据也不炸，桶就留在原地。现在交给数据的桶（连锁的 `k<o>_cn`、三连桶的第一个桶）记下来，`RECHECK` 4 tick 后再看一眼：数据炸了的桶那时已经灭了（`k<o>_live` 摘掉、位置忘掉）；还亮着、还点着、还是那个桶，就是数据的圈里一个人都没有，本包空炸并接着连锁，同英雄联盟（连到的桶一定炸）。用的是数据自己的结果，不用猜它的圈量不量身子，所以 `EMPTY_MARGIN` 不改（只决定先交给谁）。日志 `CHAIN LATE #n: keg o at (x, y) still lit 4 ticks after it was left to the data (nearest enemy D away, the data's zone 30000) - blown empty here`；`CHAIN ... left to the data` 和 `TRIPLE ... the data's` 也写上最近的敌人多远。他死在这 4 tick 里（死人的被动不跑）就不补炸。单元测试 `a_keg_left_to_the_data_is_blown_when_the_data_did_not`。下一局看 `CHAIN LATE` 里的距离：都在 30000 以外就说明数据的圈只量中心。
