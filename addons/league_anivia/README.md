# 艾尼维亚附加包（测试版 v0.1.3）

主包 `league` 保持纯数据。用户选了「主包不做蛋，寒霜涅槃只放在扩展包里」和「冰墙我要的是真的墙 可以卡住人的那种」。这个附加包用原生代码做主包数据做不到的三件事，
画面、声音、伤害仍然在主包的数据里（附加包只判断、只移动单位）：

| | 主包（不装附加包） | 装了附加包 |
|---|---|---|
| 寒霜涅槃 | **没有**（数据读不到当前生命，也没有「受到致命伤害」的时机；模拟里按危险程度变蛋的近似，会在 20%–100% 生命时触发，所以不做） | 受到致命伤害时不倒下，变成冰蛋 `egg_t` tick（6 秒）：生命回满当作蛋的生命，禁普攻、禁技能，双抗降低；**蛋被打碎才阵亡**（击杀算打碎蛋的人），撑过去就带着蛋剩下的生命孵化。每 `egg_cd` tick（240 秒）一次，**阵亡不重置** |
| 寒冰屏障（Q 晕到英雄时立墙） | 竖着的冰墙 5 秒：立墙时站在墙上的敌人被拖到她那一侧；碰到墙的敌人被减速 99%，卡在墙边 | **真的墙**：5 秒里任何单位（两边的英雄、小兵、野怪，她自己也算）的中心一进墙就放回上一 tick 的位置；立墙时站在墙上的被推到她那一侧（墙在被晕的人身后，和主包一样） |
| 霜寒刺骨翻倍 | 目标正被控制（Q 的眩晕最常见），或她的风暴已成形时翻倍（看她自己身上的标记，近似） | 目标身上有**冰冻标记**（被寒冰闪耀穿过或引爆、被成形的风暴打中后 3 秒，数据挂在每个目标身上，头顶一枚雪花）就翻倍，按每个目标判断 |

## 怎么做的

- **寒霜涅槃**：照赛恩附加包的「不死守护」：冷却好了时一直给她挂着「不死」`league_anivia_p_guard`，生命停在 1 就触发：生命设成最大值，
  挂 `league_anivia_egg_go`（6 tick）。主包数据的副本每 2 tick 看一次：看到 `egg_go` 就播缩进蛋里的动作、挂双抗降低的 `league_anivia_egg_on`，
  每 30 tick 续一次蛋的动作；`egg_t` tick 后附加包挂 `league_anivia_egg_hatch`，数据播孵化。蛋期间不再挂「不死」，致命伤害就是真的阵亡。
  别人给的「不死」（基兰的大招等）在身上时不触发。游戏 0.6.4 上还会把显示世界里她正在播的 idle / hit 换成 `egg_idle` / `egg_hit`（`src/view.rs`，
  照内瑟斯附加包的显示钩子），两次续播之间、挨打时也不闪回鸟的样子。
- **真冰墙**：数据在 Q 晕到英雄 2 tick 后立墙（她身上新出现 `league_anivia_w_cd`）。投射物信息里只有位置没有名字，所以墙心取那一 tick 她新放出、
  不在她脚下的区域的位置（副本里有一个不打任何人的标记区域 `league_anivia_w_mark` 撑满 5 秒，专门给附加包找）。
  0.1.2：墙心按「这一 tick 比上一 tick 多出来的投射物个数」找（多出来最多的那处，一样多取离她远的）。0.1.0 只认上一 tick
  那里一个投射物都没有的位置，可炸点上一 tick 就有 Q 挂的 2 tick 延时，墙的两个区域被当成旧的：游戏日志里约六成的墙
  没立起来（`WALL?` 约 950 次、`WALL` 约 550 次）；被晕的英雄离她不到 25000 时也被当成她脚下的东西丢掉（现在 3000）。
  0.1.3：0.1.2 的日志里还有约三分之一找不到（`WALL` 约 200 次、`WALL?` 约 100 次）——墙的区域可能晚一 tick 才列出来。现在 `w_cd`
  出现后 3 tick 里每 tick 都找（和出现前一 tick 比），只认至少两个区域叠在一处的位置（墙的 `w_out` 和 `w_mark`；普攻、冰锥只有一个）；
  还找不到时 `WALL?` 写下前后她的投射物个数。墙是竖着的长方形（和主包的
  `Rect` 一样，宽 `w_w`、长 `w_h`，四边各加单位半径）。
- **冰冻翻倍**：E 的冰锥打中时数据在她身上亮 1 tick 的 `league_anivia_e_now`；附加包的 `on_attack` 看到它、目标身上又有 `league_anivia_iced`，
  就把这一下伤害乘 2。

参数写在英雄数据的 `passive.params`（`{"egg_t": 360, "egg_cd": 14400, "w_t": 300, "w_w": 8000, "w_h": 50000, "ice_t": 180}`），由
`make_override.py` 从 `tools/kit/build_anivia.py` 的参数表 `P` 写入。

## 在游戏里测

1. 主包（League of Legends Heroes 0.138 以上）要装着并启用。
2. 用附加包合集 `league_addons`（里面已经包含本包），或者把整个 `league_anivia` 文件夹放进 `<游戏目录>\mods\`
   （要有 `league_anivia.dll`、`mod.mod_info`、`mod.override_info`、`override\`、`text\`）。
3. 进游戏，在 MOD 菜单里启用它（含代码的 mod 会弹一次确认），确认排在主包后面，重启游戏。
4. 看艾尼维亚的普攻说明：开头是「【附加包】」就说明换上了。
5. 日志在 `%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_anivia.log`，每次启动游戏重写（上一次的留在 `.prev.log`）：
   - `SPAWN`：出生；`EGG`：致命伤害停在 1 血、变成蛋；`HATCH`：孵化；`BROKEN`：蛋被打碎；
   - `WALL`：立墙（位置）；`WALL?`：看到立墙但没找到墙心（应该不出现）；`HOLD` / `PUSH`：把单位挡在墙外 / 推出墙；
   - `ICED`：霜寒刺骨在冰冻目标上翻倍。

## 开发

- `python addons/league_anivia/make_override.py`：从参数表重新生成 `override/` 和 `text/`（先核对主包的艾尼维亚和参数表一致）。
  主包的艾尼维亚改了以后要重跑。
- 在 `addons/` 下 `cargo test --release -p league_anivia`：单元测试（挡墙、推出墙、找墙心、别人的不死、参数、蛋的显示换图）。
- 在 `addons/` 下 `cargo build --release -p league_anivia`（Windows）得到 `target/release/league_anivia.dll`；`league_addons` 合集也会编进本包。
- 经典 SDK 的模拟器跑不了原生代码，本包只做了单元测试，要在游戏里看日志确认。
