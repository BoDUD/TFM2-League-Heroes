# 婕拉附加包（测试版 v0.2.1，可选）：种子、植物、光合作用、植物有了身体

**不装这个附加包，主包里的婕拉也是完整的**：普攻甩出荆棘种子；Q 致命棘刺在目标点炸出棘刺，落点长出荆棘喷射者；E 缠绕之根禁锢一条线上的
敌人，落点长出藤蔓鞭击者；R 绞杀之藤召唤密林，2 秒后击飞还在里面的敌人，并激怒她的植物。主包是纯数据：**数据不能在地上留东西**，所以
主包里每次 Q、E 都当场种一颗种子、马上长成植物（英雄联盟 W + Q / W + E 的连招）；植物是落点上的周期区域，每秒打区域里先轮到的一个敌人
（小兵可能排在英雄前面），伤害不随等级变。这个附加包用原生代码把英雄联盟的**种子**做出来（用户 2026-10-20：技能方案 A、中单、做附加包）。

## 怎么做的

- `mod.override_info` 把主包的婕拉换成 `override/` 里的副本（`make_override.py` 用 `tools/kit/build_zyra.py` 的 `native=1` 生成，主包的
  婕拉改了就重跑）：被动是本包的 `league_zyra:garden`（数字在 `passive.params`）；普攻、Q、E 的说明开头加【扩展包】。
- **落点**：数据告诉不了原生代码 Q、E、R 落在哪里（弹道的信息里没有名字），所以副本里 Q、E、R 出手那一 tick 给目标挂 2 tick 的
  `league_zyra_q_aim` / `e_aim` / `r_aim`（落点就是目标那时站的地方）；被动每 tick 看一遍敌方单位，新挂上的标记就是一次落地。
- **种子**：被动记下每颗种子的位置，`s_show` tick 重放一次 `league_zyra_s_seed` 的画面（种子的图一轮正好这么长），掉落时放
  `league_zyra_s_drop` 的声音（英雄联盟 W 种下种子的声音）。
- **植物**：长出来时在种子的位置放主包的 `t_plant` / `v_plant` 画面（它们的动画就是 5 秒的一生）和声音；之后被动自己数时间出手：
  荆棘喷射者 `spawn_projectile` 从植物身上吐出 `league_zyra_t_spit`（只是画面，效果是空的 `league_zyra:noop`），按距离算好飞到的 tick 再
  `deal_damage_typed` 扣血、放 `t_hit`；藤蔓鞭击者当场扣血、挂 `league_zyra_v_slow`（减速 30%）、放 `v_hit`。她死了种子和植物照样留着
  （英雄联盟的）。
- 游戏 0.6.4 的 `deal_damage_typed` 只把伤害排进效果队列，下一次 on_update 之前才扣血（莉莉娅 0.1.2 的教训）。
- 日志：`%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_zyra.log`：`SEED`（掉种子）、`GROW`（种子长成植物）、`STRIKE`（植物出手）、
  `RAGE`（激怒）、`TAKEDOWN`（参与击杀掉种子）、`WATCH`（每 30 秒的计数，植物有动静才记），都限了条数。
  v0.1.2：`SPAWN` 只在一次启动的第一行带上全部参数，`SPAWN`、`WATCH` 整个游戏一个计数（预模拟先记 40 行、之后每 100 行一行，你看的那场每行都记），
  `WATCH` 只在长了植物、植物出手、激怒或参与击杀之后才记（2026-11-03 夜里的日志 3267 行里 1399 行 `WATCH`、250 行带全部参数的 `SPAWN`）；玩法不变。
- **光合作用**（v0.1.3，2026-11-05，用户的彩蛋「植物大战僵尸」：蕾欧娜的技能命中婕拉的植物会让植物模型变大一号）：`src/sun.rs`。植物不是单位，
  「命中」= 蕾欧娜的技能落在植物站的地方；比赛里有蕾欧娜（哪一边都算）才看。认植物：种子长的在 `grow` 时记下；主包数据在 Q、E 落点长的，
  Q、E 的标记记下落点，之后落点上出现一个不动的、婕拉的弹道（植物的区域）就是它，按落地的时间（副本的 `passive.params` 里的
  `q_delay` / `q_fast` / `e_grow`）认是荆棘喷射者还是藤蔓鞭击者。认技能：蕾欧娜在动的弹道（E 的光刃）经过植物 16000 以内；她不动的弹道
  （R 的阳光）出现 37 tick 后落下、植物在 45000 以内；她身上多一层 `league_leona_eclipse_hold`（W 的日蚀爆开）、植物在她 44000 以内；
  任何单位身上多一层她的 `league_leona_sunlight`（Q、E、W、R 打中的都挂）而他站在植物 16000 以内。变大：植物自己的画面照放，本包在
  上面按同一个节奏放大一号的（x1.5，本包的 `effects/league_zyra_sun`，`tools/art/fx_zyra_sun.py`）：这一轮从下一帧放起、之后每轮开头放
  一整轮、最后放抖动和枯萎；后放的画在上面，大的盖住小的；变大时一道她的金光（`sun_pop`）。只变大一次，已经在枯萎的不变；植物的出手、
  伤害都不变。日志 `SUN #n: her R's sunlight landed on a Spitter (Q/E's) at (x, y), 120 ticks old: one size bigger from tick t`，`WATCH`
  多一项 `sunlit`（变大过几株）。没在游戏里看过：大的盖不盖得住小的、两段之间会不会闪一下，要看画面。
  v0.1.6：变大时给婕拉挂一个只有名字的 `league_zyra_sun_grew`（60 tick），league_eggs 读到了在屏幕上放提示「光合作用」。

## 在游戏里测

1. 主包（League of Legends Heroes 0.177.0 以上）要装着并启用。
2. 用附加包合集 `league_addons`（里面已经包含本包），或者把整个 `league_zyra` 文件夹放进 `<游戏目录>\mods\`（文件夹里要有 `league_zyra.dll`、
   `mod.mod_info`、`mod.override_info`、`override\`、`text\`、`effects\`）。
3. 进游戏，鼠标停在婕拉的技能上，说明开头是【扩展包】就说明副本生效了；打一局后看日志里的 SEED / GROW / STRIKE / RAGE / TAKEDOWN；有蕾欧娜的那局看 SUN（她的技能落在植物上，植物画大一号）。

## 重新生成

```bash
python tools/kit/build_zyra.py                 # 主包的婕拉（参数表 P）
python addons/league_zyra/make_override.py     # 本包的副本和说明
cargo build --release -p league_zyra           # 在 addons/ 下
```

## 0.1.6：光合作用的提示交给 league_eggs（2026-11-09）

用户：「我需要所有彩蛋都要有提示 你看看哪些没有的补进去」。光合作用（植物在蕾欧娜的阳光里变大一号）一直没有屏幕上的提示，而提示
统一由 league_eggs 画（它认 buff、击杀记录、阵容，别的附加包不用自己画）。可植物不是单位、变大只是本包放的画面，两个附加包单独装时
又是两个 DLL，league_eggs 什么也读不到。所以 `src/sun.rs` 在植物变大的那一 tick 给婕拉挂一个 `league_zyra_sun_grew`（`GREW`）：
只有名字、`GREW_T` 60 tick、同时只有一层（`entity_stack_buff` 最多 1 层，再长一株就续上时长），一项属性都没有，玩法不变。
league_eggs 0.2.0 每 tick 看婕拉身上有没有它，第一次看见时放「光合作用：蕾欧娜 的阳光照在 婕拉 的植物上，植物长大了一号」（一局一条）。
测试 `the_marker_only_tells_league_eggs`：名字、时长、除此之外全是默认值，league_eggs 读的就是这个名字（league_eggs 那边也有
测试核对本包还挂着它）。日志照旧是 `SUN`。

## 0.1.4：每种行整个启动一个计数（2026-11-06，11-06 的日志）

一次启动的预演日志 441 KB：`SEED` 1792 行、`STRIKE` 1482、`GROW` 1403、`TAKEDOWN` 811。这几种行限的是每个婕拉自己的条数（每局前 8 / 10 / 6 行、
之后每 25 / 100 行），服务器每次启动跑几百场预演、每场都是新的被动，加起来就没有上限。现在 `SEED`、`GROW`、`STRIKE`、`RAGE`、`TAKEDOWN`
也和 0.1.2 的 `SPAWN`、`WATCH` 一样整个启动一个计数（`noted`）：预演先记 40 行、之后每 100 行一行，你看的那场每行都记；行末多一个 `#k`
（这一种行的第几行），行里的 `#n` 照旧是这个婕拉的第几个。玩法不变。

## 2026-11-08 的日志：`R AIM` 认得到，`RAGE` 一直是 0（只是说明，玩法和版本都不变）

0.1.5 加的 `R AIM` 在两次启动里认到 25 次 R——认得到，副本的 `r_aim` 接上了。可 23 次 R 出手时她一株种子植物都没活着，另 2 次有一株，
离落点 66206 / 78244，激怒只管落点 `r_r`（32000）以内的，所以 `RAGE` 一直 0 行、`WATCH` 的 rages 一直是 0。这是预料之中的，不是 bug：

## 植物有了身体（v0.2.0，2026-11-14）

用户：「召唤物的全做啊 剩下的一批英雄也做了啊 都做完了装进去了再测」。召唤物第二轮（公用模块 `summon.rs`）。附加包的代码 + 主包两张单位图 `league/champions/league_zyra_spitter`、`league_zyra_lasher`（`tools/art/unit_zyra_plants.py`：植物自己的一生 `t_plant` / `v_plant` 的 1 倍帧——这张特效图是特效高清表里的，游戏按 1 倍的大小画，所以和今天一样大，不用在 league.dll 里登记：idle / run 四帧摇摆，attack 长直 → 吐刺的光 / 抽打 → 摇摆，hit 往后一格，dead 抖动、枯萎、残根、没了）。**要和带这两张图的主包一起装**。

- 英雄联盟（wiki 现行页面）：种子被 Q、E 打中长成植物，留 8 秒，不会动，能被打掉（一下近战英雄普攻、两下远程英雄普攻），打掉给 3 金币；伤害 15–82 + 20% 法强，攻速 0.8，射程 575 / 400，藤蔓鞭击者减速 30%。
- 本包的植物长出来时（种子长的、落点那株）排原生效果 `league_zyra:spitter` / `:lasher`，在它站的地方生成身体 `league_zyra_spitter` / `_lasher`：移速 1、攻击 0（射程、节奏是植物的，只为了朝着敌人、播吐刺 / 抽打的动作），生命是她上限的 15%，没有护甲魔抗，留到植物的时间结束（`t_life` + 1）。读成单位时按位置接到那株植物上；出手照旧由本包打（伤害随等级、先打英雄），从身体现在站的地方。身体被打掉（`OVER … KILLED`）这株植物就不再出手。
- 第一个身体读成单位以后她身上一直挂 `league_zyra_p_unit`：副本的数据在 Q、E 落点不再长主包的那一株（画面、声音、区域都套在 `SwitchByBuff league_zyra_p_unit` 里），改给她挂 3 tick 的 `league_zyra_q_land` / `_e_land`，本包读到就在落点（Q、E 出手时标记的那个点）长一株自己的（带身体）。落点那株因此和种子长的一样：伤害随等级、先打英雄（主包的是固定伤害、先轮到谁打谁）。
- 比赛里有蕾欧娜时植物照旧是画面：光合作用的彩蛋把植物的画面画大一号，身体画不大（要在 league.dll 里登记）。
- 退路：宿主没有 `spawn_unit`、失败（`:spitter` 照旧放植物的画面）、读不成单位、测试开关 `unit=off`——不挂 `league_zyra_p_unit`，植物照旧是画面，落点那株照旧由数据长。
- 日志（都以 `PLANT` 开头）：第二行 `PLANTS: … - ON`（测试开关）；`GROW #…, its body asked for` → `PLANT SPAWN #`（身体的单位 id、位置、数字）→ `PLANT #n LOOK #`（读回来的名字、种类、能不能选中、生命、`speed` 是不是 1；接不上植物时 `NO plant of hers stands there`）→ `PLANT UNITS ON #` → 每秒一行 `PLANT #n #k:` → `PLANT #n OVER #`（被打掉还是到时间、敌方那一 tick 拿了多少钱、`strikes no more`）→ `WAKE #`；`PLANT HOOK #`（引擎把身体那一下 0 伤害的攻击告诉被动没有）；`PLANT PICTURES #`（有蕾欧娜或测试开关：照旧是画面）；失败时 `PLANT SPAWN FAILED` / `PLANT LOST` / `PLANT UNITS OFF`。
- 测试开关：日志旁边的 `league_zyra.cfg`（`unit=off` 不生成身体、`name=<名字>` 换单位名；身体本来就是移速 1）。
- 还没做：被打的伤害按来源固定（英雄联盟：近战英雄普攻一下、远程两下）、密林激怒时多 50% 生命、植物升起来的动作（单位一出来就站着）、有蕾欧娜时的身体（彩蛋的大一号身体要在 league.dll 里登记）。

## 植物的身体站稳了再接手（v0.2.1，2026-11-14）

第一批真实对局数据（游戏 0.7.2 的预模拟）：新单位生成那一拍和下一拍，最大生命、攻击、防御、移速都读成 1，那时设的生命会被盖掉（悟空的分身生成后一拍读到 `hp 1851/1 attack 1 def 1 mr 1 speed 1`）。公用的 `Flock`（萨科附加包 0.3.1 的 `summon.rs`）现在等单位站稳（最大生命读出来）才接手：`PLANT #n LOOK` 晚一两拍、是身体自己的数字，植物和身体也在那时连上（5 次还没站稳就照样接手，行末写 `(its health cap still reads 1 after 5 looks)`）。代码没改，测试没改（假宿主里单位一生成就站稳）。
