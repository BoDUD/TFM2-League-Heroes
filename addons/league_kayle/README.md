# 凯尔升阶附加包：按真实等级升阶、死后不掉（测试版 v0.2.0）

用户：「能一直保持吗 死后不掉」。主包 `league` 保持纯数据：凯尔 5 / 8 / 12 级的升阶是她身上永久的 `league_kayle_rank5` /
`rank8` / `rank12`（12 级再加 `form3`），身后的翅膀绑在它们上。引擎在她死亡时清掉身上全部 buff，数据又没有「复活时」这个
时机，所以主包每条命第一次出手才静默补读等级：从倒下到复活后第一次出手，她没有翅膀，射程也回到近战。

这个附加包把主包的凯尔换成 `override/` 里的副本（`make_override.py` 生成），和主包有两处不同：

1. **按真实等级升阶**（0.2.0）。数据读不到等级（`SwitchByLevel3` 只分 3 级前后，大招 5 级才解锁），主包拿最大生命值当等级表：
   给自己 123 / 151 / 189 的护盾、打自己 10% 最大生命，打破了就算到了 5 / 8 / 12 级。游戏里等级表以外的生命（装备等）让它提前好几级：
   10-24 的日志（`league_kayle.log` 和 `.prev.log`）里 `rank5` 有 9 / 23 次在 3 级就来（其余在 5 级），`rank8` 11 / 23 次在
   4-6 级，`rank12` 23 次全在 6-10 级、一次也没在 12 级。经典 SDK 的模拟里几乎准时（上路 36 局只有 2 局提前一两级；
   那里她出的是法强装），所以多半是游戏里额外的生命，数据分不出来。副本里每个探测（从 `probe_shielded` 标记到给阶的
   `SwitchByBuff probe_amp`）都换成 `SwitchByBuff league_kayle_lv5` / `lv8` / `lv12`，两个分支原样保留：给的阶、金翼仪式和
   语音、接着的下一阶都和主包一样，只是到了那一级才给，也早 6 tick（不再给自己挂护盾、打自己）。副本因此从 708 KB 降到 169 KB。
   被动每 tick 按她真实的等级（`level()`）把缺的标记补上（没有数值，只是标记），死了清掉也马上补回。
   强度（`kd.py` 上路，种子 1-8，288 局；经典 SDK 跑不了原生代码，所以拿主包比）：主包按时升阶（就是本包现在的样子，数值也
   是照这个调的）团队击杀差 +1.04；把三个护盾各降 23（相当于多 230 生命，日志里的提前量）模拟游戏里提前两级左右升阶，
   +3.81。也就是说游戏里的凯尔一直比设计的强，按真实等级升阶后回到设计的强度，数值不用改。
2. **死后不掉**。被动每 tick 看一次：
   - 活着时身上有哪几阶就记下来（记在被动里，被动在玩家身上，死了不丢）；
   - 记下的阶身上缺了就原样补上，数值和主包一样（rank5 射程 +27500；rank12 攻速 +30%、移速 +10%、射程 +10000；rank8、form3
     只有画面）。死着的时候也补，倒下时翅膀还在；复活时引擎再清一次也马上补回；
   - 补过之后（或补的阶撑过了死亡）给她挂上 `league_kayle_life`，这条命就不再补读：补读不看身上已有的阶，同名 buff 会叠成
     两层，射程变两倍。

新的一阶仍在出手时由那段数据给（每 2 秒最多查一次，金翼仪式和语音照旧）；本包只补已经升过的阶，从不提前。阶的 buff 名和
数值没变，[`league_ult_press`](../league_ult_press/README.md) 按她 buff 上的射程（`buff_range`）算站桩距离照旧。提示文字没改
（主包的已经到详情面板的长度上限）。

只有单元测试（经典 SDK 跑不了原生代码），要在游戏里看日志：`%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_kayle.log`
（`LEVEL` 第一次挂上哪个等级标记，`RANK` 记下一阶——行首的 `Lv` 应该就是 5 / 8 / 12，`DEAD` / `ALIVE`，`KEEP` 补回了
哪几阶、死着还是活着，`LIFE` 跳过补读）。

```bash
python addons/league_kayle/make_override.py           # 主包的凯尔改了就重跑
python addons/league_kayle/make_override.py --check   # CI：副本是不是最新的
cd addons && cargo test -p league_kayle && cargo build --release
```
