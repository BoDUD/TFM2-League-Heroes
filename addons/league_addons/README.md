## 怎么合在一起

- 游戏一个 mod 只加载一个 DLL（`<mod_id>.dll`），所以不能把几个附加包的 DLL 放进同一个文件夹。这里把各附加包的源码当模块编进
  `league_addons.dll`（`src/lib.rs` 的 `#[path]`），每个附加包的 `register` 把自己的原生效果、被动、AI 钩子和地图读取注册进同一个
  `StableMod`。SDK 里这些都是列表（地图读取只有一个：合集的 `MapReaders` 先调卡密尔的读墙、再调雷恩加尔的读草丛），名字只是约定加前缀，所以名字照旧（`league_nocturne_dark:start`
  等），各附加包的英雄数据原样可用。
- 只能有一个的三样由合集自己设、在 `src/lib.rs` 里转发，设在所有 `register` 之后：地图读取 `MapReaders`、客户端扩展 `BundleClient`
  （佛耶戈的时钟、阿克尚的复活大字、奥恩的锻造光晕、英雄联盟彩蛋的公告和头像计数；英雄联盟大小龙 2026-11-10 起是单独的 mod，它的公告读合集导出的 `league_addons_eggs_showing` 避开彩蛋的公告）、比赛钩子 `BundleMatch`（2026-11-05 起：先卡尔萨斯的
  `Respawns`，再英雄联盟彩蛋 league_eggs 的 `Eggs`，2026-11-06 起再卢锡安开大朝向子弹的 `Aim`，最后是只读的运营、打架记录）。哪个附加包要用这三样，加进转发里，
  别在 `register` 里自己设（后设的会把前面的整个换掉，不报错）。
- `build.rs` 打开 `league_bundle`：各附加包源码里的 `declare_stable_mod!` 只在单独编译时生效，合集只导出自己的入口。
  单独编译每个附加包还是它自己的 DLL（`cargo build --release` 一次全编）。
- 数据由 `assemble.py` 合成：复制各附加包的 `override/`、`effects/`，里面和 `mod.override_info` 里的 `asset/<附加包>/` 改成
  `asset/league_addons/`；文字合并成一个 `text/champion.i18n`（键是各附加包自己的 id，如 `description.league_leesin_hop`，不会撞）；
  别的游戏文字按文件名各合并成一份（2026-11-09 起；当时是 league_dragons 改纳什男爵、元素亚龙名字的三份，它 2026-11-10 起
  单独成 mod、自己带着这三份），各配一条 `asset/base/text/<名字>` 的 merge（以前只认 `champion.i18n`，别的文字的
  remap 会照抄进来却没有文件）；
  `mod.mod_info` 要求的主包版本取各附加包里最高的。
- 合集和单独的附加包不能同时启用：两边替换同一个英雄、注册同名的原生效果。

## 生成和测试

```bash
cd addons && cargo build --release                      # 得到 target/release/league_addons.dll（和各附加包自己的 DLL）
python addons/league_addons/assemble.py <输出文件夹>       # 全部附加包；--only league_nocturne_dark,league_leesin_hop 只放已发布英雄的
```

把输出文件夹改名 `league_addons` 放进 `<游戏目录>\mods\`（先关掉单独的附加包），在 MOD 菜单里启用并排在主包后面，重启游戏。
各附加包的日志照旧各写各的（`%APPDATA%\TeamSamoyed\TeamfightManager2\data\<附加包>.log`），合集启动时每个附加包各记一行「loaded」。

## 两张 5v5 地图：原版和 Rin 的召唤师峡谷

2026-11-10 用户装了第三方地图 mod「召唤师峡谷 · 玩家 α 测试」（作者 Rin，mod id `tfm2_lol_map_test`，0.1.28-alpha.game071）：
「要同时兼容原版地图和这个地图」。开着它时每局 5v5 都在它用自己 DLL 搭的峡谷上打：1614545 见方（原版 960000），地形、寻路、
视野、三路兵线、高地塔和兵营、野怪都是原生做的，不经过我们读的地图文档。单线和死斗照旧是原版图。

- **认图**：共享模块 `game_places::terrain`（`addons/game_places/src/terrain.rs`）按塔和水晶站在哪认图：有一座过了 1000000
  就是峡谷。只看塔和水晶，不看英雄（被放逐、藏起来的英雄停在哪说不准）。
- **峡谷的墙**：读作者随 mod 发的 `地图资料/墙体坐标.json`（295 x 296 格、每格约 5454.5，从 x 约 2727 起）。把地图压缩包里的
  `地图资料` 文件夹复制进 `mods/tfm2_lol_map_test/` 即可，或用环境变量 `LEAGUE_RIFT_WALLS` 指到这个文件。它是作者的数据，
  不随我们的 mod 发。没有这个文件时，峡谷上不知道哪里是墙：撞墙类机制只认地图四边外，不会像以前那样把 960000 以外全当成墙。
  地图 mod 升级后墙可能变：日志里写着文件版本和装着的地图版本，不一样时有 `STALE?`。
- **草丛**：峡谷没有草丛数据，草丛类功能在峡谷上都关掉。艾翁 W 的草丛照常算。
- **离墙留一格**：附加包在峡谷上推人、钩墙、挑落点用的是墙向外加厚一格的格子（`terrain::rift_ground`，一格约 5454.5，和作者寻路的半径 5000 相当：用作者的寻路网格对过，走不到的点 0.0% 被当成能站）。以前贴墙的落点有两成站不了人，英雄停在那里就走不动（用户：「有的地方会走路卡住」）。
- **原版地图**：行为一点不变，所有旧测试原样通过。
- **日志**：每个附加包第一次碰到峡谷时，在自己的日志里记一行 `== Rift: … ==`（读到墙体文件没有、版本对不对）。
  `league_macro_log` 每张图记一次 `MAP` 行：每座塔和水晶、第一条小龙和第一只男爵在哪、被藏起来的英雄停在哪。
- **别同时开 `league_rift`**：我们自己的 5v5 地图 mod 也换底图、小地图，还挪塔和野怪。
