# 娜美附加包（v0.1.0）

主包 `league` 保持纯数据。用户 2026-11-14 看了「和英雄联盟不一样的地方」清单后说「全改吧」，再说「接着做」（能做的小项都做）。英雄联盟的唤潮之佑（E，wiki："empowering their next 3 basic attacks or abilities to each deal bonus magic damage and slow enemies for 1 second"，6 秒）强化被祝福者接下来的三次命中；这里没有第四个技能位，主包把它并进冲击之潮（Q），数据又读不到别人的出手，只能做成「被治疗的人 4 秒内攻击力、法强 +15%，水流打中的敌人减速 25%」。这个附加包用原生代码做成英雄联盟的样子：

| | 主包（不装附加包） | 装了附加包 |
|---|---|---|
| 唤潮之佑（并在 Q 里） | 被冲击之潮治疗的人 4 秒内攻击力、法强 +15%；水流打中的敌人减速 25%（1 秒） | **接下来的 3 次命中**：被治疗的人（她自己也算）6 秒内接下来 3 次普攻或技能，每次多造成 50 + 20% 娜美法强的魔法伤害并减速 25%（1 秒）；水流自己不再减速 |

## 怎么做的

- 副本（`override/`，`make_override.py` 从主包的 `league/champion/league_nami.data_champion` 生成）和主包一样，只是冲击之潮给的 `league_nami_e_blessing`（四处：先治疗队友或她自己、再弹到下一个人）不再加攻击力、法强，挂 `BLESS_T`（360 tick = 6 秒）；水流打中敌人时的 `league_nami_e_slow` 去掉；被动换成本包的 `league_nami:tide`，冲击之潮的说明换成本包的。祝福的画面照主包。
- 谁在出手、打中了谁：游戏的接口读不到「这一下是谁打的」，本包照 league_milio 的做法看两样（`src/allies.rs`，复审后改的）：① 观察钩子 `league_nami:watch`（每个玩家都挂，她自己也挂，优先级最低，只记不改）记下每个玩家的 AI 最后一次下令普攻 / 放技能对准的是谁——技能对准友方（治疗、护盾、给队友的技能）的不算，普攻、技能对准塔、水晶的不算；② 带着祝福的英雄冷却跳起来（刚出手）后，那个人得真的掉了血：有人带着祝福时被动每 tick 记下敌方单位（塔、水晶除外）的生命 + 护盾掉了多少（她自己补的那一下扣掉），冷却跳起前 40 tick 到之后 45（普攻）/ 60（技能）tick 里，命令对准的那个人掉了血才算；没有命令目标时取他 95000 以内、掉得够多（他攻击力 / 法强的 25%）的最近的一个。往前也看是因为引擎在动作结束时才开始走冷却。同一次掉血不给一个人的两下各算一次。
- 每次：打中的那个人受到 `DMG` + `DMG_AP`% 娜美法强的魔法伤害（50 + 20%，英雄联盟 20–80 + 20% 的中间一级；算娜美的），减速 `SLOW`% `SLOW_T` tick（25%、1 秒，主包水流的数；换掉旧的不叠），播主包普攻的水花，用掉一次。祝福新挂上或被刷新就是满的 3 次，第三次打中时摘掉祝福。她自己的冲击之潮（唤潮之佑并在里面）不算一次：给自己祝福的那一下（第 8 tick 祝福挂上、动作结束时冷却才跳）不会用掉自己的祝福；她的普攻、碧波之牢、怒涛之啸照算。
- 她阵亡时被动不跑：那段时间祝福不生效，照样到时消失。

## 在游戏里测

1. 主包（League of Legends Heroes 0.354 以上）要装着并启用。
2. 用附加包合集 `league_addons`（里面已经包含本包），或者把整个 `league_nami` 文件夹放进 `<游戏目录>\mods\`（要有 `league_nami.dll`、`mod.mod_info`、`mod.override_info`、`override\`、`text\`）。
3. 进游戏，在 MOD 菜单里启用它（含代码的 mod 会弹一次确认），确认排在主包后面，重启游戏。
4. 看娜美的冲击之潮说明：开头是「【附加包】」、唤潮之佑写着「6秒内3次命中各多造成」就说明换上了。
5. 日志在 `%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_nami.log`，每次启动游戏重写（上一次的留在 `.prev.log`）：`SPAWN`：出生 / 复活；`BLESS`：谁拿到祝福；`TIDE`：谁的第几次命中打了谁、多少伤害。

## 开发

- `python addons/league_nami/make_override.py`：从主包重新生成 `override/` 和 `text/`（`--check` 只比较，CI 用）。主包的娜美改了以后要重跑（主包的祝福变了脚本会停下）。
- 在 `addons/` 下 `cargo test --release -p league_nami`：单元测试（每次的伤害、新祝福 / 刷新是满的 3 次、冷却跳起算出手、副本的祝福不带加成、挂 6 秒、水流不再减速、调本包的被动）。
- 经典 SDK 的模拟器跑不了原生代码，本包只做了单元测试，要在游戏里看日志确认。
