# 索拉卡附加包（v0.1.0）

主包 `league` 保持纯数据。用户 2026-11-14 看了「和英雄联盟不一样的地方」清单后说「全改吧」，再说「接着做」（能做的小项都做）。英雄联盟的祈愿（R，wiki："increased by 50% on targets below 40% of their maximum health"）给生命低于 40% 的友军多回复 50%；被动拯救（wiki，V14.4 起 90%："Soraka gains 90% bonus movement speed while facing nearby allied champions that are below 40% of their maximum health"，作用半径 2500）朝生命低的友军跑时大幅加速。数据读不到任何人的当前生命，也读不到她往哪走，主包只能给每个人一样多、把拯救近似成「W 施放后 2 秒移速 +30%」。这个附加包用原生代码补上这两条：

| | 主包（不装附加包） | 装了附加包 |
|---|---|---|
| 祈愿（R） | 全图所有友方英雄（包括她自己）各回复 220 + 60% 法强 | **生命低于 40% 的多回复 50%**（110 + 30% 法强，合计 330 + 90%）：落下那一刻读每个人的生命，别的人照旧 220 + 60% |
| 拯救（被动） | W 施放后 2 秒移速 +30%（W 的说明里叫「被动拯救」） | **朝附近（2500 码 = 250000）生命低于 40% 的友方英雄走时移速 +90%**；W 施放后 2 秒 +30% 照旧（说明里不再叫拯救） |

## 怎么做的

- 副本（`override/`，`make_override.py` 从主包的 `league/champion/league_soraka.data_champion` 生成）和主包一样，只是：大招那一圈治疗的最前面加了本包的原生效果 `league_soraka:wish`；挂上本包的被动 `league_soraka:salvation`（`passive.params`：`ms` 90、`low` 40、`reach` 250000、`cone` 45，`src/lib.rs` 的常量写进去）；W 和大招的说明换成本包的。
- `wish`：圈里的每个友方英雄先过这一步，再吃主包的治疗，所以读到的是治疗之前的生命。这个人的生命低于最大生命的 `LOW_HP`%（40%）就用 `heal` 多回复主包那一下的 `BONUS`%（50%），头上多一个绿色数字；不低的什么都不做。法强读的是索拉卡施放时的。主包那一下的数值（`HEAL` 220、`HEAL_AP` 60%）写在 `src/lib.rs`，`make_override.py` 和单元测试核对副本里的治疗是不是这个数，主包改了就停下。
- `salvation`（每个索拉卡一份，两边都选她各算各的）：每 3 tick 看一次她这 3 tick 走的方向（走了不到 300 算站着，一下过去 30000 以上是闪现、传送，都不算）。方向上（左右 45° 以内：wiki 没写角度）有一个中心离她 250000 以内、生命低于 40%、活着、选得中的友方英雄（她自己、召唤物、分身不算；骑在别人身上的悠米选不中，英雄联盟 V11.2 起也不算），就挂 5 tick 的 `league_soraka_salvation_run`（移速 +90%），每次看到还朝着就续上（`entity_stack_buff`，一份）；转开、站住、那人回了血或死了，下一次看就摘掉。她死了什么都不做（复活后从头量方向）。每次看最多读十个英雄，不分配内存。
- W 施放后 2 秒 +30%（主包的 `league_soraka_salvation`）照旧：经典 SDK 的模拟跑不了原生代码，副本拿掉它时 W 每局少放 7.6 次（种子 1-8：54.3 -> 46.7，9-16：54.4 -> 46.9，各 240 局），击杀差 +1.32 -> +0.50、+0.57 -> -0.05——本包只加英雄联盟的规则，不动主包的数。两个加速名字不同，各算各的、加在一起。
- AI 的打分不变：多回复的那一半、拯救的加速都不在数据里。

## 在游戏里测

1. 主包（League of Legends Heroes 0.354 以上）要装着并启用。
2. 用附加包合集 `league_addons`（里面已经包含本包），或者把整个 `league_soraka` 文件夹放进 `<游戏目录>\mods\`（要有 `league_soraka.dll`、`mod.mod_info`、`mod.override_info`、`override\`、`text\`）。
3. 进游戏，在 MOD 菜单里启用它（含代码的 mod 会弹一次确认），确认排在主包后面，重启游戏。
4. 看索拉卡的说明：大招开头是「【附加包】」、最后一句是「生命低于40%的多回复50%」；W 开头是「【附加包】」、最后一句是「被动拯救：朝附近生命低于40%的友方英雄走去时移动速度提高90%」，就说明换上了。
5. 日志在 `%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_soraka.log`，每次启动游戏重写（上一次的留在 `.prev.log`）：
   - `SPAWN #1: the add-on's Soraka (player 4, team 0), Params { ms: 90, low: 40, reach: 250000, cone: 45 }`：这局的索拉卡是附加包的副本；
   - `WISH`：谁在祈愿落下时生命低（生命 / 最大生命、百分比），多回复了多少；
   - `SALVATION #3: toward 盖伦#12 at 310/1100 (28%), 84000 away, 12 deg off -> +90% move speed`：加速亮起（每次从没有到有记一行）：朝着谁、他的生命、多远、方向偏几度。
   - 都是前 60 次和之后每 100 次记一行。

## 开发

- `python addons/league_soraka/make_override.py`：从主包重新生成 `override/` 和 `text/`（`--check` 只比较，CI 用）。主包的索拉卡改了以后要重跑。
- 在 `addons/` 下 `cargo test --release -p league_soraka`：单元测试（40% 的界线、多回复的量是主包那一下的一半、副本在主包的治疗前面调本包、主包的数值没变；拯救的参数是副本的、方向和 45°、250000 的界线、站着和闪现不算、加速是一份 5 tick 的 buff、副本的 W 除了说明和主包一字不差）和 `tests/wiring.rs`（走真实的导出入口，迷你模拟里每 tick 调被动：朝低血队友走就加速、转身 / 站住 / 回血 / 死了 / 敌人 / 太远 / 闪现都没有、她死了不动、两边都选她各看各的、和 W 的 +30% 互不干扰）。
- 经典 SDK 的模拟器跑不了原生代码，本包要在游戏里看日志确认。
