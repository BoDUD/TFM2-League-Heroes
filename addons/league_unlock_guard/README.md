# 解锁总闸附加包（v0.1.0，在附加包合集里）

用户（2026-10-18，过日卡死三次之后）：「加上总闸：合集里加一个排在最后的检查，锁着的技能 2 / 大招换成普攻或原地站一下并记日志」。

游戏 0.6.4 的「输入合法」（`ctx.is_valid_input`）既不看冷却也不看解锁：AI 钩子在大招解锁（5 级）前按 R、技能 2 解锁（3 级）
前按技能 2，引擎照样放出来；游戏自带的 AI 看到正在施法的敌方英雄时，5 级以下（技能 2 是 3 级以下）读到类型为空的默认数据，
`unwrap` 崩溃（`game-ai` 的 `battle.rs:447`、`act_gates.rs:111`，`log.log` 里的 `panic occurred`），出在后台比赛线程里——那一局
永远打不完，过日卡死。当时是 league_ult_press 0.4.0（崔斯特、克格莫）和 league_bard 的争龙钩子，PR #337 修好；#339 把其余 18 个
带 AI 钩子的附加包都看过，都不会这样按（[合集 README](../league_addons/README.md) 的「AI 钩子按技能 2、大招前先看解锁」）。
每个钩子自己先查格子是规矩；这个包是兜底：以后哪个钩子忘了，最多让英雄站一下，不会再卡死过日。

| | 不装（或单独的附加包） | 装了合集（含本包） |
|---|---|---|
| 钩子在解锁前按技能 2 / 大招 | 引擎放出来，敌方的 AI 崩溃，那一局打不完，过日卡死 | 改成普攻输入点的那个敌方单位；点的是自己人、地点、方向或普攻不合法，就原地站一下 |
| 别的输入、已解锁的格子 | — | 不改 |
| 游戏自带的 AI 自己的按键 | — | 不改（它从不按锁着的格子） |

只有游戏自带 AI 的主包没有钩子，用不着它；它只管附加包合集 DLL 里的钩子。

## 怎么做的

- AI 钩子 `league_unlock_guard:gate` 挂在所有英雄上，优先级 `i32::MAX`。引擎按优先级从小到大跑钩子、每个拿到前一个的决定
  （最后替换的为准；烈娜塔的狂暴是 1_000_000），所以它看到的是所有钩子改完的最终输入。单元测试核对别的附加包源码里没有
  `i32::MAX`（谁也排不到它后面），以及合集确实注册了它。
- 最终输入是技能 2 / 大招时读那个格子的 `CooldownV1::unlocked`（SDK：技能 2 在 3 级前、大招在 5 级前为 false）：
  - 解锁了，或读不到冷却（ABI 10 以前的游戏）：不改；
  - 锁着、输入点的是活着的敌方单位：改成普攻它（`is_valid_input` 不收这次普攻就站着）；
  - 锁着、没有能普攻的目标：走到自己脚下，等于原地站一下。
- SDK 的钩子只能「不改 / 替换」，撤不掉一个按键，所以只能换成别的输入；引擎这一 tick 原来的决定拿不到（要的话得再加一个最低
  优先级的钩子记下来，现在没做）。
- 开销：几乎每个 tick 都没有新命令、或者只是走路 / 普攻，第一行就返回；只有按技能 2 / 大招时多读一次冷却。

## 日志

`%APPDATA%\TeamSamoyed\TeamfightManager2\data\league_unlock_guard.log`，每次启动游戏重写（上一次的留在 `.prev.log`）：

- 第一行 `=== league_unlock_guard v0.1.0 (...) loaded: game 0.6.4 abi 10 ... ===`：总闸在；
- `GUARD [presim m=比赛 s=第几局] t=<tick> <英雄>#<实体> player <玩家> lvl<等级> Ult pressed while locked at <目标> -> ATTACK #<目标> #<第几次>`
  （或 `-> STAND`）：拦下了一次。正常对局里一行都不该有；有就说明那个英雄的某个钩子少了解锁检查，照英雄去查它的附加包。
- 每个英雄、每个格子先记 20 次，之后每 1000 次一行，一次启动最多 5000 行（哪个钩子每 tick 都按也写不爆日志）。

## 开发

- 在 `addons/` 下 `cargo test -p league_unlock_guard`：单元测试（哪些输入有等级锁、锁着时换成什么、日志限量、没有别的钩子排在它后面、
  合集注册了它）。
- `league_addons` 合集把本包编进去（`src/lib.rs` 的 `#[path]` 和 `unlock_guard::register`）；单独 `cargo build --release -p league_unlock_guard`
  也能得到它自己的 DLL，但单独装的附加包各自一个 DLL，总闸管不到别的 DLL 里的钩子，所以只在合集里用。
- 工作区路径太长时链接会失败（LNK1104），用短的 `CARGO_TARGET_DIR`（如 `C:\t\ul_target`）。
