# TFM2-League-Heroes

团战经理2（Teamfight Manager 2）的英雄联盟英雄 Mod，mod_id 是 `league`。英雄本身都是数据（`league/`）；主包从 0.97.0 起带一个自己的 DLL（`league.dll`，源码 [`addons/league_main`](addons/league_main/src/lib.rs)，`mod.mod_info` 是 `contains_code` / `native`，订阅时游戏会提示这是代码 mod），只做数据做不到的事：高清帧（PPU）、界面小图集、选人卡片的动画、音频预读（高清帧和小图集的画法在 [`addons/hd_engine`](addons/hd_engine/src/lib.rs)，和 tft 包的 `tft.dll` 共用）。仓库里还有第二个 mod `tft`（金铲铲之战系列，源文件在 [`tft/`](tft/)），和一组可选的原生代码附加包（[`addons/`](addons/)，合成一个 `league_addons`）。

- **每位英雄现在的技能、附加包、高清帧和开发记录**：见下面的 [英雄一览](#英雄一览)，或者 [`docs/heroes/`](docs/heroes/) 里每位英雄一页；表格版是 [`docs/heroes.xlsx`](docs/heroes.xlsx)。
- 原来 README 里很长的技术说明搬到了 [`docs/tech-notes.md`](docs/tech-notes.md)，演示动图在 [`docs/gallery.md`](docs/gallery.md)，不属于某位英雄的几节在 [`docs/dev-notes.md`](docs/dev-notes.md)，性能调查在 [`docs/perf.md`](docs/perf.md)。

2026-11-26（凯尔、艾达斯的选人格子；选人格子的值不再有 0 和正数）：

- **为什么蕾欧娜会冒出格子**（用户：「为什么会有这问题」，然后「一起修」）：`banpick_center` 照 `-39 - 待机最高的一格` 算，最高的一格是剑尖、翅膀尖时会算出 0 或正数；正数不许用就写成了 0，可游戏把 `{0, 0}` 当成没设（按 -12 摆、不裁），我们自己的 `tools/art/bp_card_audit.py`、`tools/art/hero_reels.py` 却把 0 当成正常的值，所以一直查不出来。
- **凯尔**也是 `{0, 0}`（翅膀尖 -40，算出 +1 被压成 0），翅膀冒出格子顶约 12 游戏像素：改成 **-1**（翅膀只裁掉最尖的 1 格，小腿在名字栏下面；-4、-7 会把翅膀裁平）。**艾达斯**（`tft_idas`）是 +1（接入时待机顶 -40 算的，后来她的待机顶只到 -33.3，而且正数从来不对：易大师以前 +5 时格子画成了 1 倍）：照规则改成 **-6**，`tools/kit/setup_idas.py` 的 `VIEW` 一起改。三个人的选人格子帧表都不用变（`hero_reels.py --check`）。
- **检查工具照游戏算**：`bp_card_audit.py` 和 `hero_reels.py` 把 `{0, 0}` 当成没设；表里标出 `ZERO=NONE` / `POSITIVE`，规则算出来不会是 0 或正数（那时量头，或者取 -1）。新的 `bp_card_audit.py --check` 进了 CI：哪个包的 `champion_view` 里有 `{0, 0}` 或正数就失败（在改之前的 main 上正好报出凯尔、蕾欧娜、艾达斯三个）。
- 主包 0.475.0、云顶包 0.79.0（只换两份数据文件，league.dll、tft.dll 不变）。

## 安装测试

英雄的音频（英雄联盟的音效和配音）版权属于 Riot Games，**不提交到仓库**，要先在本地从英雄联盟客户端提取：每位英雄的提取命令在他那一页「开发记录」的「重新生成」里（`tools/lol/extract_<英雄>.py`），通用说明见 [盖伦那一页的「从本地英雄联盟提取音频和图标」](docs/heroes/league_garen.md#从本地英雄联盟提取音频和图标)。装进游戏和上传创意工坊都用 `tools/package_mod.py` 打包，不要直接复制 `league` 文件夹：

```bash
pip install pillow numpy soundfile
python tools/package_mod.py --install                  # 全部英雄装进 Teamfight Manager2/mods/league
python tools/package_mod.py --hero fiora --install     # 只装一个英雄，别的英雄的文件不动
python tools/package_mod.py --out <文件夹>/league       # 打包到别处，例如上传创意工坊用的文件夹
python tools/package_mod.py --src tft --hero powder --install   # tft 包（第一次装要在 Mods 菜单里勾上）
```

然后在游戏的 Mods 菜单里启用 `league`。打包时会编译并带上 `league.dll`（需要 cargo），还会给每位英雄打出界面小图集（`ui_sheets/`）。日志在 `%APPDATA%\TeamSamoyed\TeamfightManager2\data\league.log`。

游戏启动时会把 mod 里除背景音乐外的每个文件整个读进内存，原样复制的 `league` 有 78 MB，其中 66 MB 是 WAV。打包后的内容和仓库里完全一样，只是更小（19 MB）：

- 音效转成 MP3（和原版音效同一格式），名字不变。
- 音频放在 `sound/bgm/`（2026-10-17）：游戏对这里的 mp3 / wav 是播放时才打开，启动时不读，启动要开的文件少了四成（5282 → 3194，机械盘上文件分散时冷启动 88 → 51 秒）。`.sound_info` 还在 `sound/sfx/`，每个音频的 override 指到新位置。游戏第一次播放时在主线程打开文件，所以 `league.dll` 在标题画面出来后把这些音频预读进系统缓存，比赛里第一次响不用等盘。
- 精灵图的图集去掉重复帧、排紧，每一帧的大小和像素不变。
- JSON 去掉空白。
- 英雄的技能效果树去掉不起任何作用的包装（[`tools/kit/slim.py`](tools/kit/slim.py)：套在别的效果列表里的 Combine、只包一个效果的 Combine、两个分支相同的 SwitchByBuff、两个分支开头或结尾相同的效果提到分支外面），执行的效果、顺序、时机都不变。游戏每 tick 都要把每个英雄的 skill、skill2 整棵复制一遍，节点越少越省 CPU（2026-10-18，全部英雄的 skill + skill2 少约 5%，各英雄另外的等价改写见 [docs/perf.md](docs/perf.md) 第 8 节）；附加包合集 `assemble.py` 组装时也这样处理。

每个输出都会和源文件核对。仓库里的文件不变。查到的原因和数字见 [docs/perf.md](docs/perf.md)。

## 附加包

主包 `league` 的英雄不装任何附加包也是完整的。数据做不到的事（读当前生命、读墙和草丛、整身变身、按参与击杀算……）由可选的原生代码附加包补上，全部合进一个 mod **附加包合集 `league_addons`**（玩家只多订阅一个；怎么合、怎么编译和组装见 [`addons/league_addons/README.md`](addons/league_addons/README.md)）：

```bash
cd addons && cargo build --release                      # 得到 target/release/league_addons.dll（和各附加包自己的 DLL）
python addons/league_addons/assemble.py <输出文件夹>       # 全部附加包；--only a,b 只放其中几个
```

把输出文件夹改名 `league_addons` 放进 `<游戏目录>\mods\`（先关掉单独的附加包），在 MOD 菜单里启用并排在主包后面，重启游戏。合集和单独的附加包不能同时启用。

- 每位英雄有哪些附加包、改了什么，见下面英雄一览的「附加包」一列和英雄页里的「附加包」一节（从各附加包的 `mod.override_info`、`README.md` 和文字生成）。
- 单独的 mod（不在合集里，模组列表里单独开关，`assemble.py` 的 `STANDALONE`）：[`league_dragons`](addons/league_dragons/README.md)（英雄联盟的大小龙、龙魂、远古巨龙、纳什男爵）、[`league_hextech`](addons/league_hextech/README.md)（海克斯大乱斗：比赛里按等级三选一的海克斯）。
- 不属于某一位英雄的：[`league_ult_press`](addons/league_ult_press/README.md)（游戏 AI 不按或很少按的技能替它按、被 AI 停住时替英雄平 A）、[`league_ult_aim`](addons/league_ult_aim/README.md)（大招挑英雄联盟玩家会挑的目标）、[`league_unlock_guard`](addons/league_unlock_guard/README.md)（兜底：哪个 AI 钩子在技能 2 / 大招解锁前按了，换成普攻或原地站一下并记日志，免得过日卡死）、`league_recall_log`（回城日志，诊断用）、`league_macro_log`（运营日志，诊断用：每场写塔、大小龙、大龙后干了什么、到了对面基地又走掉）、`league_fight_log`（打架日志，诊断用：每场写各位置死了几次、死在哪、团战谁先死、射手被贴脸有没有人救、谁在挨打）、`league_ai_watch`（AI 日志，诊断用：敌方英雄在普攻距离内、普攻也好了时游戏的 AI 让每个英雄干什么，普攻和技能各出手几次）（游戏自带比赛 AI 的逆向笔记：[docs/native_ai.md](docs/native_ai.md)），以及共用的 [`addons/game_places`](addons/game_places/src/lib.rs)（运行时在 EXE 里找地址，见下）。`league_ult_press`、`league_ult_aim` 管到的英雄，英雄页的「附加包」一节也列出了和他有关的几行。
- 附加包里的英雄副本由各自的 `make_override.py` 从主包生成：**主包改了英雄就要重跑**，CI 会用 `--check` 核对（见 [持续集成](#持续集成)）。

## 高清帧（PPU）和界面

详细的来龙去脉见 [docs/tech-notes.md](docs/tech-notes.md)（「高清帧」「画风统一」「待机和选人卡片的动画」「界面小图集」「两个包共用的高清帧引擎」「平涂像素画」各节）。要点：

- **高清帧**：登记在 [`addons/league_main/src/hd.rs`](addons/league_main/src/hd.rs)（tft 包的在 [`addons/tft/src/hd.rs`](addons/tft/src/hd.rs)）`HEROES` 里的英雄（每位的 PPU 见英雄一览，画出来的大小 `SIZES`）在自己的图里多一套 `hd_<动作>` 帧，每帧是 1 倍帧的 PPU 倍大。游戏里画出来大小不变、像素细 PPU 倍：高清帧引擎 [`addons/hd_engine`](addons/hd_engine/src/lib.rs)（`league.dll` 和 `tft.dll` 共用）挂在游戏按名字取动画表和贴图的函数上，把每个动作换成高清帧、矩形和贴图尺寸除以 PPU；战场画真实的高清帧、实体的绘制缩放写成 1/PPU。两个包都开着时，先加载的那个 DLL 挂钩、画两个包的英雄，后加载的只把自己的表交给它（[`src/share.rs`](addons/hd_engine/src/share.rs)），Mods 菜单里谁先谁后都一样。没有 DLL 或游戏版本不认得时，照旧画 1 倍帧。
- **工具**：[`tools/art/ppu_hd.py`](tools/art/ppu_hd.py) 把高清帧写进图里（`python tools/art/ppu_hd.py --hero <英雄>`）；[`tools/art/ppu_restyle.py`](tools/art/ppu_restyle.py) 把原来的高清帧（`assets/source/ppu/orig/`）统一成泽丽那样「像素多但清晰」的画风（每个游戏像素约 2.2 格）；[`pack_ppu_strips.py`](tools/art/pack_ppu_strips.py) / [`import_ppu_strips.py`](tools/art/import_ppu_strips.py) 把动作打包给美术重画、再读回；[`ppu_one.py`](tools/art/ppu_one.py) 把 1 倍帧按高清帧缩回。
- **界面**：图鉴、头像、选人槽位、选中特写用每个游戏像素 1.5 格的 `lo_<动作>` 帧；选人网格（BP 格子）用战场那套 `hd_` 帧播 `bp` 动画（[`tools/art/hero_reels.py`](tools/art/hero_reels.py)：只用图里已有的帧重排，挑哪几帧记在 [`hero_reels.json`](tools/art/hero_reels.json)）；待机 `idle` 不再上下呼吸，而是定住、随机冒一个小动作。
- **界面小图集**：一屏画全部英雄时，整张战斗图集装不进游戏原本 256 MiB 的 GPU 图片缓存，BP 和英雄界面每帧都在重新解码。所以 `tools/package_mod.py` 给每个英雄打出两张只有界面帧的小图集（`ui_sheets/idle/`、`ui_sheets/bp/`），高清帧引擎让界面改画它们（[`src/ui.rs`](addons/hd_engine/src/ui.rs)），战场照旧。见 [docs/perf.md](docs/perf.md) 第 9 节。
- **GPU 图片缓存**：小图集的预算后来也满了，`league.dll` 又把游戏的缓存从 256 MiB 放大到 1.5 GiB（[`src/cache.rs`](addons/league_main/src/cache.rs)）。找不到缓存对象时不改，日志写原因。

## 游戏版本更新时

高清帧引擎（`league.dll` / `tft.dll`）和整身变身的附加包要在游戏的 EXE 里找函数。[`build.rs`](addons/hd_engine/src/build.rs) 列着认得的游戏版本（现在是 0.7.4、0.7.3、0.7.2、0.7.1 和 0.7.0），逐字节核对每一处要改、要调用的代码；对不上（游戏更新了）就由 [`addons/game_places`](addons/game_places/src/lib.rs) 在运行时按特征码找（日志 `game build: found at run time in … ms`），找不到或不唯一才退回 1 倍帧；只是界面画英雄的五处认不全时（0.7.2 改过一次），战场照样高清，只有界面不用小图集。游戏改了代码形状时：

```bash
python tools/re/find_build.py        # 从上一版 build.rs 在新 EXE 里重新找出地址，更新 build.rs（界面某处认不出：--drawer <k>=<rva>）
```

## 踩坑记录

最近几周吃过的亏，以后照这些做。细节在各条的链接和英雄页的「开发记录」里。

**数据和机制**

- **存档里有每位英雄的一份副本。** 生涯开始时，游戏把全部英雄的定义抄进存档（7 套规则，每套一整份）。之后改了英雄的数据（`.data_champion`、附加包的 override），已经开着的生涯还是旧的；只有附加包的代码改动会生效。
  - 装完数据，先用 [`tools/save/refresh_save_heroes.py`](tools/save/refresh_save_heroes.py) `存档` 报告哪些副本过期，再加一个输出路径写新存档（存档里的平衡补丁按比例保留）并读回核对，直到 0 份过期。
  - 画面（view）不在存档里，只改图不用刷。
- **游戏自己会打平衡补丁，mod 英雄也打。** 每个补丁按数据挑英雄加强或削弱，不分原版和 mod。赛季开始时还会改比赛规则（比赛太长就改塔的血量和击杀金币），调过的比赛节奏会被它改回去。
- **区域的 `first_delay` 写 0 不是「马上生效」。** 区域出现后要过一整个周期才第一次生效；一次性的区域（周期比持续时间长）写 0 就永远不生效。要立刻生效写 1。25 位英雄的 42 个区域都是这样改的，奥瑞利安·索尔的大招在这之前一直打不中人（[#700](https://github.com/BoDUD/TFM2-League-Heroes/pull/700)）。
- **加射程不要用 buff 的 `range`。** AI 会站到加长后的距离，普攻却只在动作自己的射程里出手，结果站着不打（克格莫 W）。用官方的 `range_adjust`：主包统一走 league.dll 的 `league:range` 标记（[#703](https://github.com/BoDUD/TFM2-League-Heroes/pull/703)），`tools/kit/range_buffs.py --check` 在 CI 里核对。
- **普攻要对自己做的事，放到弹道命中后，别放在出手时。** 普攻的效果树里、弹道命中之外，有目标是自己或友军的 `RangeEffect`（自动开的技能、计数、整套技能轮询的启动），游戏的 AI 就几乎不下「打这个英雄」的指令：奥瑞利安·索尔每存活分钟 0.06 次、阿兹尔 0.07、德莱文 0.16、卡莎 0.60，别的射手 4.5～7 次、法师 2.3～3.3 次，补兵、放技能照常。把这一块原样包进一发朝普攻目标飞的隐形弹道（晚一拍执行），游戏里量到卡莎 5.5（91 局）、阿兹尔 1.9（66 局）、德莱文 6.5，技能次数不变。现有英雄由打包器统一包（[`tools/kit/attack_self.py`](tools/kit/attack_self.py)）：52 位包进这发隐形弹道；包不了的（同一拍别的效果要读这一块写的东西，或者普攻自己的伤害可能先落地、打死人后弹道就打空了）17 位改用第二种载体——每一块放进一发一拍落在自己身上的隐形抛射物，游戏里量到泰达米尔 0.95 → 4.32（130 局）、亚索 1.03 → 2.71（26 局）、李青 1.00 → 1.58（138 局），克格莫不带它 3.37、带它 6.52；另外 7 位量到本来就正常，保持原样（`--check` 列出全部名单）。所以装进游戏的文件有这些隐形抛射物、仓库里的没有，手抄 `.data_champion` 进游戏要抄打包后的那份；新英雄直接写在普攻弹道的命中效果里。给这种普攻加 `league:range` 节点试过，没有用。引擎到底读了什么还没找到，见 [docs/native_ai.md](docs/native_ai.md)。
- **英雄死了，他放下的区域和召唤物还在跑。** 从投射物 `end_effects` 起的区域比施法者活得久，而施法者的 buff 停在死前的状态。茂凯死后，他的树苗每 tick 都在放音效、打伤害（[#668](https://github.com/BoDUD/TFM2-League-Heroes/pull/668)）。区域里真正生效的部分要包一层「施法者活着」。
- **游戏里英雄一死，玩家身上就没有英雄实体了。** 从死到复活，附加包读到的 `champion()` 是空的；复活后是一个新实体（克格莫从 #21 变成 #1020 这样的大号），身上的 buff 也是新的，每条命第一次出手挂的 `Permanent` 标记会重新挂上。他自己的钩子死后不跑，要在他死后做事、或者找他死前放出去的投射物，得由活着的英雄的钩子按他死前那个实体的编号去找（`league_ai_watch` 的 `KOG` 几行，2026-11-14，91 场预模拟加 1 场观战）。克格莫只靠数据做的死后虚空分身在游戏里看不到，正在用这几行日志查原因。
- **数据里的放逐（`Banish`）不看 `cc_immune`。** 塔姆可以吞开着护盾的希维尔。要判断免疫，只能在附加包的代码里做（[#612](https://github.com/BoDUD/TFM2-League-Heroes/pull/612)）。
- **游戏自带的 AI 不打躲在泉水里的敌人，但会在旁边等。** 卡尔萨斯的灵体原来留在死的地方，敌人就围着等；改成灵体回泉水后，敌人就散了（[#737](https://github.com/BoDUD/TFM2-League-Heroes/pull/737)）。
- **n tick 的标记只在 n−1 个 tick 里读得到。** `ult_cooldown_mult` 会把大招剩余冷却封顶在 冷却 /(1 + m/100)，可以拿来做返还冷却。`tools/kit/check_arm_refund.py` 在 CI 里核对这两点。
- **区域的画面放出来就停不下来。** 地面这类该跟着状态走的画面，如果放成一个长区域，状态提前结束后画面还会留满时间，看着就像规则坏了。卡蜜尔 R 就是这样：她被击退出场地、阵亡以后，地面还留着，用户问「卡密尔离开磁场后 磁场也不消失？」。改成让附加包在状态还在时，每几 tick 放一段投射物画面，状态一没就不再放（[#773](https://github.com/BoDUD/TFM2-League-Heroes/pull/773)）。

**美术和 PPU**

- **重画的模型不能一帧大一帧小。** Codex 常把整个人画大来填满轮廓，也会只把头画大。每帧要量头，还要量一个硬部件（武器上的宝石、剑柄），按身体缩放，而不是只按头（瑟提、基兰、慎）。
- **黑边在游戏里有多粗，按「格数 × 大小 / PPU」算。** Codex 画的描边落到细格子上本来就有两三格，`ppu_restyle.py` 的 `edge` 还会再加一圈；PPU 低的英雄就显得黑边粗（菲兹 4 格 / 1.81 = 2.2 个游戏像素，发条 2 格 / 2.25 = 0.89 才正常）。重跑流水线后要再跑 [`tools/art/thin_outline.py`](tools/art/thin_outline.py)，CI 的 `--check` 会提醒（[#768](https://github.com/BoDUD/TFM2-League-Heroes/pull/768)）。 收细要从外面削掉多出来的一圈，不能把里面的描边涂成身体色，那样身体会长进原来的描边里（菲兹头顶多一块，[#769](https://github.com/BoDUD/TFM2-League-Heroes/pull/769)）。从英雄帧派生的图（俄洛伊的灵魂、克格莫的虚空形态、亚托克斯的悬空帧）要跟着重跑，`illaoi_souls.py` 没有 `--check`，不会自己报过期。
- **图像模型交回来的图要自己逐帧看。** 它自己的验收只和底稿比，照着底稿的 8×8 方块整块照抄也算通过，但这样放进游戏和原来一样，要退回重画。
- **读回重画时，软边的细线和小点会被读粗。** 小圆点会读成十字，细斜线会读成两倍粗；所以读回只能落在原来的方块里，方块外面只补台阶的内角。
- **皮肤的隐藏部件以 bin 里的 `initialSubmeshToHide` 为准。** 以前按名字猜，把卡尔萨斯、茂凯、塞恩的整个身体都藏了（[#726](https://github.com/BoDUD/TFM2-League-Heroes/pull/726)，`tools/lol/hide_audit.py`）。
- **界面一次要画全部英雄。** 整张战斗图集装不进游戏原本 256 MiB 的 GPU 缓存，BP 和英雄界面会卡。现在每位英雄另打两张界面小图集，league.dll 还把缓存放大到 1.5 GiB（见 [高清帧（PPU）和界面](#高清帧ppu和界面)）。
- **审动画要用像素原样的动图。** 带缩放平滑（LANCZOS）和 255 色调色板的动图会糊掉描边、合并颜色：丽桑卓 38 种颜色只剩 17 种原样，用户看到的「失去像素」「莫名其妙的阴影」其实是预览的毛病。每个像素用最近邻放大、纯色底、颜色全部保留，再给人看。
- **跑步别做成木偶。** 同一张原画放两帧、第二帧只让上身往下沉而腿停着，看起来像木偶（奎桑提、阿萝拉、妮蔻）；锁住画好的动作（奥拉夫的头盔）、重画手臂（赵信）也都被退回。腿一格不动，身体随落脚起伏，节奏按联盟放慢。
- **整只手臂一起挪，会和脸共用的那条描边拉开。** 扎克变瘦后，跑步里画面右边那只手臂整只左右挪 1 格，从肩到腋下和脸共用一条描边，往外挪就是 2 格宽的黑缝（有一行透出背景）。肩膀和上臂要跟着身体走，只让下巴以下的前臂和手摆。
- **「看着很活」的跑步保留前，也要按一个不动的部件把每帧对齐了查。** 呲呲第 5 帧画了两个鞍、身体和尾巴一帧长一帧短，艾达丝的头和远古石甲虫背上的石头一帧大一帧小，第一眼都看不出来。
- **两条腿画得一样，就看不出交叉步。** 4 帧只画了一步、两条腿同色时，看起来永远是同一条腿在前（希尔科、苍蓝雕纹魔像）。做成两步一圈，第二步要么前后腿一深一浅，要么把那一帧里两条腿自己的画对调；只差一档深浅在游戏里看不出来，要差两档。
- **两个分支各修一次同一个工具问题，会修出两种结果。** `keep_lo` 和 `pad` 一起用时，赛芬那次让留下的 lo_ 帧保持原大小，岩宝那次把它们居中放大；合在一起时加一个默认关的键（`keep_lo_centred`），两人的 `--check` 都要对上。
- **握着东西的手要在游戏大小下看。** Codex 改手臂时，锐雯握剑的拳头只画了 3 × 3 格，游戏里大约 2 个像素，用户：「感觉右手和没了一样」。拳头至少要和另一只手一样大；锐雯换成了她 E 冲刺时那只 5 × 4 的拳头（[#773](https://github.com/BoDUD/TFM2-League-Heroes/pull/773)）。

**安装和发布**

- **league.dll 和附加包合集都是整个文件装的。** league.dll 里内嵌了每位高清英雄的帧表，附加包合集也是一个 DLL。如果用一个缺了「已装但还没合并的 PR」的分支编译再装，那个 PR 的英雄和修复就被换回去了。所以装之前，要把所有已装、未合并的 PR 临时合在一起编。
- **只装几个文件时，图集要拿 `package_mod.py` 打包后的那份，`#sheet.png` 和 `#anim.fanim` 成对装。** 仓库里的图集摆得宽：2026-11-15 那 81 位英雄，仓库里合计 1.79 亿像素，打包后 1.31 亿。图和帧表要同一来源；league.dll 内嵌的帧表只读动作名和宽度，不读位置，所以装打包后的图没问题。
- **装之前确认游戏已关闭，进程名是 `TeamfightManager2.exe`。** 文件夹名有空格，进程名没有；用错名字会以为游戏没开，结果 DLL 被占用、写不进去。
- **`make_override.py --check` 只对 CI 列表里的附加包是只检查。** 其余附加包的这个脚本会直接重写 `override/` 和 `text/`。
- **main 要求 CI 通过才能合并。** CI 加进来之前切出的分支，PR 会一直等一个不会来的检查，要先把 main 合进分支。
- **生涯里一个 mod 英雄都没有。** 新建生涯时「英雄类型」默认是「经典」，mod 英雄不在经典名单里。要选「自定义」→ 英雄设置 → 全选；代码 mod 还要在 Mods 菜单里手动启用一次，再重启游戏。

**性能**

- **掉帧先看是哪块显卡在画。** 显示器接在主板（核显）上时，游戏在核显上画，独显闲着；实测核显 93–99% 满载。把显示器接到独显，或在 Windows 设置的「图形」里给 `TeamfightManager2.exe` 选高性能显卡。
- **别的 mod 也会拖慢。** 第三方的「防御塔镀层」比赛中每 5 秒往盘里写一次观战压缩包，可能造成周期性的小卡顿。
- **游戏每 tick 都要深拷贝每位英雄的技能树。** 技能树越大越费 CPU，写新英雄时要让 `skill` / `skill2` 保持精简（[docs/perf.md](docs/perf.md) 第 8 节，skill 里也有这条规矩）。

## 金铲铲之战系列（tft 包）

第二个 mod，mod_id `tft`，名字「Teamfight Tactics Heroes」，源文件在 [`tft/`](tft/)：金铲铲之战（云顶之弈）里英雄联盟没有的棋子——爆爆（[`tft_powder`](docs/heroes/tft_powder.md)）和诺拉（[`tft_norra`](docs/heroes/tft_norra.md)，技能照英雄联盟手游）。爆爆的音效是游戏本体自带的音频片段（在她自己的 `.sound_info` 里叠起来播），诺拉的是从英雄联盟客户端借的片段（和主包一样不进仓库，`tools/lol/extract_norra.py` 提取、打包时带上）。tft 包是原生 mod：数据做不到的地方写在它自己的 `tft.dll` 里（[`addons/tft`](addons/tft/README.md)，每个 tft 英雄一个模块，现在是诺拉的手游规则），打包时编好带上，所有 tft 英雄都在这一个 mod 里。高清帧是 `tft.dll` 自己的（0.42.0 起；以前借 `league.dll`，只有两个包都开着时才有）：表在 [`addons/tft/src/hd.rs`](addons/tft/src/hd.rs)，画法是和 `league.dll` 共用的 [`addons/hd_engine`](addons/hd_engine/src/lib.rs)——只开 tft 包也有高清帧；两个包都开着时先加载的那个 DLL 挂钩、画两个包的英雄，后加载的把表交给它，Mods 菜单里谁先谁后都一样。`tft.dll` 的日志在 `%APPDATA%\TeamSamoyed\TeamfightManager2\data\tft.log`。工具链共用：`python tools/package_mod.py --src tft --hero powder --install` 装进 `<游戏>/mods/tft`，`ppu_hd.PACKS` 把她们的图写进 `tft/champions/`，`lint_mod.py tft` 检查。

## 英雄文档怎么生成

英雄一览、[`docs/heroes/`](docs/heroes/) 里每页的上半部分和 [`docs/heroes.xlsx`](docs/heroes.xlsx) 都由 [`tools/docs/gen_hero_docs.py`](tools/docs/gen_hero_docs.py) 按仓库里**现在的**数据生成（不联网）：名字和技能说明来自 `league/text/champion.i18n`（简体中文，去掉颜色和图标），冷却、距离、数值来自 `league/champion/<id>.data_champion`，PPU 来自 `addons/league_main/src/hd.rs` 和 `addons/tft/src/hd.rs`，附加包来自 `addons/*/mod.override_info`、`README.md` 和 `text/`，动图是 `docs/preview/<id>_*.gif`，头像是待机第一帧（`docs/heroes/img/`）。改了英雄、加了英雄或附加包之后重跑：

```bash
pip install pillow openpyxl                                   # 头像要 pillow，xlsx 要 openpyxl（都不是 mod 的依赖）
python tools/docs/gen_hero_docs.py                            # 写英雄页、这里的英雄一览和 docs/heroes.xlsx
python tools/docs/gen_hero_docs.py --released <已发布名单>      # xlsx 里填「工坊已发布」（一行一个英雄 id，如 ahri）
python tools/docs/gen_hero_docs.py --check                    # 只检查：有页面或英雄一览过期就返回 1（不看 xlsx 和头像）
```

- 每页 `## 开发记录` 以下是手写的，生成时原样保留：**新英雄的设计、美术、音效、改动说明写在这里**，不再写进 README。分路从「开发记录」表格的「定位」一行读（`| 定位 | 上单（……）|`），没有这一行的在脚本的 `LANE_FALLBACK` 里补。
- README 里只有 `<!-- HEROES:BEGIN -->` 和 `<!-- HEROES:END -->` 之间是生成的，其余手写。
- 脚本可以重复跑，结果一样；在稀疏检出（没有图和动图）的工作区里也能跑，缺的文件从 git 的 HEAD 读。

## 仓库里的 skill

`.claude/skills/tfm2-hero-mod/` 是一个团战经理2英雄 mod 开发 skill。在本仓库里用 Claude Code 时会自动加载。

| 路径 | 内容 |
|---|---|
| `SKILL.md` | 英雄从数据到上架的完整流程，以及防止"静默失效"的硬规则 |
| `references/mod-structure.md` | mod 文件结构、`mod.mod_info` / `mod.override_info`、资源路径、本地测试、官方上传器 |
| `references/champion-data.md` | `.data_champion` 全字段、时间和距离单位、官方英雄的属性和冷却区间、54 种可用效果类型、buff 字段、特效绑定、常用写法 |
| `references/art-spec.md` | 像素画规范（实测数据）、动画 tag 和帧时长、锚点、特效和图标风格、AI 生成图的导入方法、QA 清单 |
| `references/text-audio.md` | 多语言文本、富文本颜色和图标、`champion_view`、音效 |
| `references/porting-heroes.md` | 把 LoL、Dota 的技能移植到 TFM2：机制对照表、选英雄评分法、LoL 客户端文件提取 |
| `references/workshop-page.md` | 创意工坊页面模板：缩略图、演示动图、收藏页、简介、更新说明 |
| `scripts/lint_mod.py` | 整包校验：路径、动画 tag、特效绑定、文本 key、音效注入、override 目标等 |
| `scripts/tfm2_ase.py` | 精灵图查看、预览和量化：身高、描边、颜色数、半透明像素等 |
| `scripts/strips.py` | 把 AI 生成的动作条导入成游戏精灵图：切帧、对齐、像素化、调色板、描边、导出 |
| `scripts/regrid.py` | 把图像模型按游戏大小画的「像素画」（边缘发虚、方块大小不匀）按它自己的格子读回，一格一个像素 |
| `scripts/bundle_tool.py` | 只读浏览游戏本体资源：可引用的原版特效、音效名、官方英雄数据 |
| `scripts/sdk_probe.rs` | 用经典 mod SDK（game_core 0.5.1）引擎自己的类型解析技能或单个效果：查可用的枚举值、引擎忽略的字段、默认值 |
| `templates/mymod/` | 可直接复制的示例 mod，已通过校验 |

## 快速开始

```bash
pip install pillow numpy
python .claude/skills/tfm2-hero-mod/scripts/lint_mod.py league
python .claude/skills/tfm2-hero-mod/scripts/tfm2_ase.py metrics <英雄>.aseprite
python .claude/skills/tfm2-hero-mod/scripts/bundle_tool.py sfx --grep fighter
```

脚本会在常见的 Steam 路径里找游戏。找不到时加上 `--game "<Teamfight Manager2 目录>"`，或者设置环境变量 `TFM2_GAME_DIR`。

在别的项目里也想用这个 skill：把 `.claude/skills/tfm2-hero-mod` 复制到 `~/.claude/skills/`。其他支持 SKILL.md 格式的工具，复制到它们各自的 skills 目录即可。
